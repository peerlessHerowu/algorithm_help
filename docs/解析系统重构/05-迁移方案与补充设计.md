# 迁移方案与补充设计

## 一、v1 → v2 数据迁移方案

### 1.1 现状分析

**v1 数据模型（`explanations` 表）：**
- 一题一级别一条最新记录（version 机制）
- 内容存在 `sections` 字段（JSON 格式的文本）
- 由 AI 凭空生成，无原始题解来源

**v2 新增（`enriched_solutions` 表）：**
- 一题一级别可多条记录
- 基于真实题解丰富生成
- 有来源追溯 `source_solution_id`

### 1.2 迁移策略：并存 + 渐进替换

```
Phase 1: 两表并存
  - explanations 保留，继续服务已有数据
  - enriched_solutions 新建，新生成的内容写入此表
  - 前端优先读 enriched_solutions，无数据时 fallback 到 explanations

Phase 2: 存量迁移
  - 后台任务逐步将 explanations 中的优质内容迁移到 enriched_solutions
  - 迁移时 source_solution_id = null, sourceType = 'LEGACY_V1'

Phase 3: 废弃旧表
  - 确认所有题目都有 enriched 数据后
  - explanations 标记为 deprecated
  - 前端移除 fallback 逻辑
```

### 1.3 前端数据源路由逻辑

```typescript
async function fetchExplanations(problemId: string, level: number) {
  // 优先查 enriched
  const enriched = await api.get(`/enriched/${problemId}/level/${level}`);
  if (enriched.data.total > 0) {
    return { source: 'enriched', data: enriched.data.items };
  }
  // fallback 到 v1
  const legacy = await api.get(`/explanations/${problemId}?level=${level}`);
  return { source: 'legacy', data: [legacy.data] };
}
```

### 1.4 API 兼容层

```java
/**
 * 统一解析查询服务：优先 enriched，fallback 到 legacy
 */
@Service
public class UnifiedExplanationService {

    private final EnrichedSolutionRepository enrichedRepo;
    private final ExplanationRepository legacyRepo;

    public List<ExplanationDTO> getExplanations(String problemId, int level) {
        // 优先查 enriched
        List<EnrichedSolution> enriched = enrichedRepo
            .findByProblemIdAndLevelAndStatus(problemId, level, "PUBLISHED");
        if (!enriched.isEmpty()) {
            return enriched.stream()
                .map(this::toDTO)
                .toList();
        }
        // fallback
        return legacyRepo
            .findByProblemIdAndLevelAndIsLatestTrue(problemId, level)
            .map(e -> List.of(toLegacyDTO(e)))
            .orElse(List.of());
    }
}
```

CREATE TABLE enriched_solutions (
    id VARCHAR(64) PRIMARY KEY,
    problem_id VARCHAR(64) NOT NULL,
    level INT NOT NULL,
    source_solution_id VARCHAR(64),
    source_type ENUM('COMMUNITY','AI_ORIGINAL','OFFICIAL','LEGACY_V1') NOT NULL DEFAULT 'COMMUNITY',

    -- AI 处理元数据
    ai_provider VARCHAR(32),
    processing_steps JSON,
    quality_score FLOAT DEFAULT 0,

    -- 版本管理
    version INT DEFAULT 1,
    is_latest BOOLEAN DEFAULT TRUE,

    -- 展示控制
    sort_order INT DEFAULT 0,
    recommended BOOLEAN DEFAULT FALSE,
    status ENUM('DRAFT','PUBLISHED','REJECTED','PENDING_REVIEW') DEFAULT 'DRAFT',

    -- 用户反馈统计（冗余存储，异步更新）
    view_count INT DEFAULT 0,
    upvote_count INT DEFAULT 0,

    -- 时间
    created_at BIGINT,
    updated_at BIGINT,

    INDEX idx_problem_level (problem_id, level, status),
    INDEX idx_status (status),
    INDEX idx_recommended (problem_id, level, recommended),
    INDEX idx_version (problem_id, level, source_solution_id, version)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

## 三、管线步骤与现有代码的对照

### 3.1 v1 管线（当前 ContentPipeline.java）

```
加载题目 → LeveledGenerator(凭空生成) → MultiLangCodeGenerator → DiagramService
         → ApproachComparator → QualityValidator → 持久化到 explanations
```

### 3.2 v2 管线（EnrichmentPipeline，新建）

```
加载题目 + 查询 top N 原始题解
  → [1] ErrorCheckStep      — 检查原始题解代码错误（新增）
  → [2] SourceFilterStep    — 从 N 条中筛选适合目标级别的子集（新增）
  → [3] PolishStep          — 基于筛选结果 + prompt 模板润色（新增）
  → [4] MultiLangStep       — 复用 MultiLangCodeGenerator（改造）
  → [5] VisualizationStep   — 复用 DiagramService（改造）
  → [6] DiversityCheckStep  — 去重/差异化检查（新增）
  → [7] QualityScoreStep    — 复用 QualityValidator 打分（改造）
  → 持久化到 enriched_solutions
```

### 3.3 复用与改造对照

| 现有组件 | v2 中角色 | 改造点 |
|---------|---------|--------|
| `LeveledGenerator` | **不再使用**（v2 不凭空生成） | 保留作为无原始题解时的 fallback |
| `MultiLangCodeGenerator` | 复用为 `MultiLangStep` | 接口适配 EnrichmentStep |
| `DiagramService` | 复用为 `VisualizationStep` | 接口适配 |
| `ApproachComparator` | 可选步骤（L3+ 使用） | 无大改 |
| `QualityValidator` | 复用为 `QualityScoreStep` | 输出从 pass/fail 改为 0-1 分数 |
| `ContentPipeline` | 保留，处理 legacy 请求 | 不修改 |

### 3.4 LevelClassify 步骤的真正语义

澄清：`SourceFilterStep`（原名 LevelClassify）的作用是**筛选匹配**而非**重新分级**：

```java
/**
 * 从 top N 原始题解中筛选适合目标级别的子集
 *
 * 筛选逻辑：
 * - L1: 选解释清晰、无复杂代码的题解作为类比素材
 * - L2: 选有完整代码 + 注释的初学者友好题解
 * - L3: 选含多种解法对比的题解
 * - L4: 选含边界分析、复杂度证明的题解
 * - L5: 选引用论文或有深度数学推导的题解
 */
public class SourceFilterStep implements EnrichmentStep {
    @Override
    public EnrichmentResult process(EnrichmentContext ctx) {
        List<CrawledSolution> filtered = ctx.getSources().stream()
            .filter(s -> matchesLevel(s, ctx.getTargetLevel()))
            .sorted(byRelevanceScore())
            .limit(ctx.getConfig().getMaxSourcesPerLevel())
            .toList();
        ctx.setFilteredSources(filtered);
        return EnrichmentResult.ok();
    }
}
```

## 四、质量保障与去重机制

### 4.1 quality_score 评分来源

```
quality_score = 自动评分(70%) + 用户反馈修正(30%)
```

**自动评分维度（QualityValidator 改造）：**

| 维度 | 权重 | 检查内容 |
|------|------|---------|
| 结构完整性 | 25% | 是否包含规范要求的所有段落 |
| 代码正确性 | 25% | 代码是否能通过基本语法检查 |
| 内容丰富度 | 20% | 字数、代码行数、图解数量 |
| 无跳步检查 | 15% | 是否有"显然""容易看出"等禁用词 |
| 多语言覆盖 | 15% | 是否覆盖所有配置语言 |

**用户反馈修正：**
- 每次 upvote → score += 0.01（上限 +0.3）
- 每次 downvote → score -= 0.02（下限 -0.3）
- 异步定时任务每小时重算一次

### 4.2 去重/差异化检查（DiversityCheckStep）

防止同一题目同一级别的多条解析大同小异：

```java
/**
 * 差异化检查：确保新生成的解析与已有内容有足够差异
 *
 * 检查方式：
 * 1. 标题相似度 < 0.7（Jaccard 分词对比）
 * 2. 核心思路段落相似度 < 0.6（余弦相似度 / 编辑距离）
 * 3. 使用的算法模式不完全重复
 *
 * 不通过时：标记为 REJECTED，记录原因"与已有解析 {id} 相似度过高"
 */
public class DiversityCheckStep implements EnrichmentStep {
    private static final double TITLE_THRESHOLD = 0.7;
    private static final double CONTENT_THRESHOLD = 0.6;
    // ...
}
```

### 4.3 L1 级别特殊处理

明确 L1 的数据约束：
- `code_implementations` = null（前端不渲染代码 Tab）
- `tags` 不含技术标签，只含类比标签如"生活类比""故事化"
- `quality_score` 评分维度不含"代码正确性"和"多语言覆盖"

## 五、安全设计

### 5.1 内容安全

| 层级 | 措施 | 说明 |
|------|------|------|
| AI 输出 | Prompt 约束 | 模板中明确禁止生成非法/不当内容 |
| 后端存储 | 内容审核队列 | 新内容状态为 DRAFT → 自动检查 → PUBLISHED/PENDING_REVIEW |
| 前端渲染 | DOMPurify | Markdown 渲染后经过 HTML sanitize |
| 前端渲染 | CSP Header | 阻止内联脚本执行 |

### 5.2 自动审核规则

```java
/**
 * 自动审核通过条件（全部满足才自动发布）：
 * 1. quality_score >= 0.6
 * 2. 不含黑名单词汇（脏话、广告、政治敏感）
 * 3. 代码块语法正确（能通过基础 AST 解析）
 * 4. 非首次生成（首次生成的题目需人工审核）
 */
```

### 5.3 版权标注规范

基于社区题解生成的 enriched 内容：
- 必须在 `source_author` 字段记录原作者
- 必须在 `source_url` 字段记录原始链接
- 前端展示时在卡片底部显示：「基于 @{author} 的题解丰富」+ 原始链接
- 来源标记胶囊（🏷️ 基于社区题解）本身就是版权声明的一部分
