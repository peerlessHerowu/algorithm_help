# 内容解析系统 v2 设计方案

## 一、核心理念变更

### 从"AI 凭空生成"到"基于真实题解 + AI 丰富"

| v1（当前） | v2（目标） |
|-----------|-----------|
| AI 根据题目描述凭空生成解析 | AI 基于爬取的高赞题解进行丰富/润色/分级 |
| 一题一级别只有一条解析 | 一题一级别可有多条解析（列表形式） |
| 直接展示完整内容 | 列表 + 展开/收起交互 |
| 没有原始题解对照 | 新增"原始题解" Tab |

## 三、数据流架构

```
采集层                    AI 处理层                    存储层                 展示层
┌─────────┐            ┌──────────────┐           ┌─────────┐          ┌────────┐
│LeetCode │──top N──→  │  AI Pipeline │──分级──→  │enriched_│──API──→  │ 前端   │
│题解采集  │            │              │           │solutions│          │列表展开 │
└─────────┘            │ 1.纠错检查    │           └─────────┘          └────────┘
     │                 │ 2.内容润色    │
     │                 │ 3.多语言补全  │           ┌─────────┐
     └──原始保存──→    │ 4.分级分类    │           │crawled_ │──API──→  原始题解Tab
                       │ 5.可视化增强  │           │solutions│
                       └──────────────┘           └─────────┘
```

### 关键设计点

1. **原始数据和 AI 处理后的数据分开存储**
   - `crawled_solutions`：爬取的原始题解（已有）
   - `enriched_solutions`：AI 丰富后的解析（新建）

2. **处理管线可插拔**：每个处理步骤独立，可配置开关

3. **与 v1 并存**：`explanations` 表保留，前端优先读 enriched，无数据时 fallback 到 legacy（详见 05-迁移方案）

4. **异步生成**：用户触发后返回 taskId，前端轮询进度，完成后刷新列表（详见 04-API设计）

## 四、数据模型设计

### 4.1 enriched_solutions 表（AI 丰富后的解析）

```sql
CREATE TABLE enriched_solutions (
    id VARCHAR(64) PRIMARY KEY,
    problem_id VARCHAR(64) NOT NULL,       -- 关联题目
    level INT NOT NULL,                     -- 1-5 分级
    source_solution_id VARCHAR(64),         -- 来源的原始题解 ID（可为空=纯 AI 生成）
    
    -- 内容
    title VARCHAR(256) NOT NULL,            -- 解析标题
    summary VARCHAR(500),                   -- 摘要（列表展示用）
    content MEDIUMTEXT,                     -- 完整 Markdown 内容
    
    -- 多语言代码（JSON: {"python":"...","java":"...","go":"...","cpp":"..."}）
    code_implementations JSON,
    
    -- AI 处理元数据
    ai_provider VARCHAR(32),               -- 使用的 AI provider
    processing_steps JSON,                 -- 经过了哪些处理步骤
    quality_score FLOAT,                   -- 质量评分（0-1）
    
    -- 展示控制
    sort_order INT DEFAULT 0,              -- 排序权重
    status ENUM('DRAFT','PUBLISHED','REJECTED') DEFAULT 'DRAFT',
    
    -- 时间
    created_at BIGINT,
    updated_at BIGINT,
    
    INDEX idx_problem_level (problem_id, level),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 4.2 配置项

```yaml
content:
  enrichment:
    # 每题采集多少条原始题解作为 AI 输入
    source-top-n: 10
    # 每题每级别最多产出多少条丰富解析
    max-per-level: 5
    # AI 处理管线步骤（可配置开关）
    pipeline-steps:
      - error-check: true        # 纠错检查
      - polish: true             # 内容润色
      - multi-lang: true         # 多语言代码补全
      - level-classify: true     # 分级分类
      - visualization: true      # 可视化增强（适用时）
    # 支持的代码语言
    languages:
      - python
      - java
      - go
      - cpp
    # 可扩展语言（启用后自动补全）
    extra-languages: []
```

## 五、AI 处理管线设计（可插拔）

```java
// 管线接口
public interface EnrichmentStep {
    String getName();
    boolean isApplicable(EnrichmentContext ctx);
    EnrichmentResult process(EnrichmentContext ctx);
}

// 上下文
public class EnrichmentContext {
    Problem problem;                    // 题目信息
    List<CrawledSolution> sources;      // 原始题解（top N）
    int targetLevel;                    // 目标级别
    String promptTemplate;              // 对应级别的 prompt 模板
    Map<String, Object> config;         // 动态配置
}

// 已有步骤
class ErrorCheckStep implements EnrichmentStep { ... }
class PolishStep implements EnrichmentStep { ... }
class MultiLangStep implements EnrichmentStep { ... }
class LevelClassifyStep implements EnrichmentStep { ... }
class VisualizationStep implements EnrichmentStep { ... }

// 未来可扩展
class CommentHighlightStep implements EnrichmentStep { ... }  // 提取评论精华
class DiagramGenerateStep implements EnrichmentStep { ... }   // 生成流程图
```

### 管线执行流程

```
输入：题目 + top N 原始题解 + 目标级别
  ↓
[1. ErrorCheck] 检查原始题解中的代码/逻辑错误
  ↓
[2. SourceFilter] 从 N 条中筛选适合目标级别的子集（非重新分级）
  ↓
[3. Polish] 按目标级别的 prompt 模板润色内容
  ↓
[4. MultiLang] 补全缺失的语言实现（如只有 Python 则补 Java/Go/C++）
  ↓
[5. Visualization] 判断是否需要可视化（链表/树→图解，DP→状态表）
  ↓
[6. DiversityCheck] 与已有 enriched 内容对比，确保差异化
  ↓
[7. QualityScore] 自动评分（结构/代码/丰富度/规范）
  ↓
输出：EnrichedSolution（含 content + code_implementations + quality_score）
      → 自动审核 → PUBLISHED 或 PENDING_REVIEW
```

> **SourceFilter 说明**：这一步是"筛选匹配"而非"重新分级"。
> 用户已指定目标级别，此步骤从 top N 原始题解中挑选最适合该级别的素材子集。
> 例如：目标 L5 时优先选含论文引用/数学推导的题解；目标 L1 时选解释通俗的。

## 六、前端组件设计

### 6.1 AI 深度解析列表组件

```tsx
// 每个级别下的解析列表
<EnrichedSolutionList problemId={id} level={selectedLevel}>
  {solutions.map(sol => (
    <CollapsibleCard
      key={sol.id}
      title={sol.title}
      summary={sol.summary}
      sourceTag={sol.sourceSolutionId ? '基于社区题解' : 'AI 原创'}
      qualityScore={sol.qualityScore}
    >
      {/* 展开后的内容 */}
      <MarkdownRenderer content={sol.content} level={selectedLevel} />
      {/* 多语言代码 Tab */}
      {sol.codeImplementations && (
        <CodeBlock code={sol.codeImplementations} />
      )}
    </CollapsibleCard>
  ))}
</EnrichedSolutionList>
```

### 6.2 CollapsibleCard 组件（新增）

- 默认收起：只显示标题 + 摘要 + 来源标记
- 点击展开：显示完整 Markdown + 多语言代码
- 支持"全部展开/全部收起"操作
- 动画过渡

### 6.3 原始题解 Tab

- 直接展示 `crawled_solutions` 表数据
- 排序：按点赞数 / 按时间
- 筛选：按包含的编程语言
- 同样用 CollapsibleCard 展开/收起
- 标记来源平台（LeetCode/LintCode/...）

## 七、扩展性设计

### 7.1 多数据源扩展

```java
// 数据源接口（已有 adapters 模式）
public interface SolutionSource {
    String getPlatform();
    List<RawSolution> fetchTopSolutions(String problemId, int topN);
}

// 已有：LeetCode
// 未来：LintCode、NowCoder、Codeforces
```

### 7.2 AI Provider 扩展

配置 `ai.default-provider` 即可切换，已支持：
- kiro-cli（当前使用）
- openai / anthropic / ollama（已有代码）

### 7.3 语言扩展

`content.enrichment.languages` 配置项加入新语言即可，MultiLangStep 自动补全。

### 7.4 级别扩展

虽然当前固定 L1-L5，但数据模型用 `INT` 存储，Prompt 模板为独立文件，新增级别只需：
1. 加一个 `L6-xxx.md` 模板文件
2. 配置项中增加级别定义
3. 前端 LevelTabs 组件已支持动态渲染

### 7.5 展示组件扩展

原始题解 Tab 未来可加：
- 标签筛选（按算法模式过滤）
- AI 摘要（一句话概括每条题解的核心思路）
- 对比视图（选两条题解并排对比）

## 九、待确认问题（已决议）

| 问题 | 决议 |
|------|------|
| L1 级别是否需要多语言代码？ | **不需要**，L1 禁止代码，`code_implementations = null` |
| 原始题解能否触发"AI 丰富"？ | **Phase 1 仅管理员**，后续考虑开放给用户（消耗额度） |
| 列表排序规则？ | 默认按 `quality_score` 降序，`recommended=true` 置顶 |
