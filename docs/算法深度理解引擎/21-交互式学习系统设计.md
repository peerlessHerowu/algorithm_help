## 一、产品定位

### 1.1 为什么交互式学习是差异化核心

认知科学中有个核心结论（来自 04-认知科学方法论.md）：

> **自我解释效应（Chi et al., 1989）**：让学习者用自己的话解释"为什么每步有效"，学习效果翻倍。
> **测试效应（Roediger）**：测试比反复阅读记忆效果好。
> **纠错学习**："纠错"比"被教"记忆效果更强。

这四个交互模式分别对应：

| 模式 | 认知科学依据 | 学习效果 |
|------|------------|---------|
| 费曼模式 | 自我解释效应 | 暴露理解漏洞，强制输出 |
| 苏格拉底追问 | 渐进式引导，激活主动思考 | 培养独立解题能力 |
| Debug 训练 | 错误驱动学习 | 建立"踩坑记忆"，敏感度更高 |
| 反向费曼 | 纠错比被教效果更强 | 通过发现错误深化正确认知 |

### 1.2 当前状态

已有：WebSocket 基础设施（5种消息类型）、页面骨架（/feynman、/socratic、/training/debug、/training/reverse-feynman）
缺失：会话持久化（interactive_sessions=0条）、轮次计数、评分报告、导出、反馈闭环

## 二、统一会话基础设施

### 2.1 WebSocket 消息协议

```typescript
// 所有交互模式共用的消息格式
interface WSMessage {
  type: WSMessageType;
  sessionId: string;
  payload: Record<string, any>;
  timestamp: number;  // UTC毫秒
}

type WSMessageType =
  // 客户端 → 服务端
  | 'USER_INPUT'          // 用户输入（费曼/苏格拉底/反向费曼）
  | 'DEBUG_SUBMIT'        // 提交 Debug 答案
  | 'REQUEST_HINT'        // 请求提示（苏格拉底）
  | 'REQUEST_SUMMARY'     // 请求生成总结（费曼结束时）
  | 'SESSION_RESET'       // 重置当前会话
  | 'SESSION_END'         // 主动结束会话
  | 'AUTH'                // 连接后认证（5秒内必须发送）

  // 服务端 → 客户端
  | 'AI_RESPONSE'         // AI 回复
  | 'AI_STREAMING'        // AI 流式输出（每个 chunk）
  | 'SYSTEM_MESSAGE'      // 系统提示（轮次警告等）
  | 'SUMMARY_READY'       // 结构化总结生成完成
  | 'SESSION_EXPIRED'     // 会话已过期
  | 'ERROR'               // 错误消息
  | 'RATE_LIMIT'          // 触发频率限制
```

### 2.2 会话数据模型

```sql
CREATE TABLE interactive_sessions (
    id              VARCHAR(36)  PRIMARY KEY COMMENT '会话ID (UUID)',
    user_id         BINARY(16)   NOT NULL    COMMENT '用户ID',
    session_type    ENUM('feynman','socratic','debug','reverse_feynman') NOT NULL,
    problem_id      VARCHAR(100) NOT NULL    COMMENT '关联题目',
    level           TINYINT      NOT NULL DEFAULT 2 COMMENT '解析级别',

    -- 状态
    status          ENUM('active','paused','completed','expired') NOT NULL DEFAULT 'active',
    round_count     SMALLINT     NOT NULL DEFAULT 0 COMMENT '已完成轮次数',
    max_rounds      SMALLINT     NOT NULL DEFAULT 20 COMMENT '最大轮次（费曼20/苏格拉底无限）',

    -- 内容（90天后清空，只保留统计摘要）
    messages_json   LONGTEXT     COMMENT '完整对话记录 JSON（90天保留期）',
    summary_json    TEXT         COMMENT '结构化总结 JSON',
    metadata_json   TEXT         COMMENT '模式专属元数据 JSON（评分/提示级别等）',

    -- 统计摘要（永久保留）
    score           FLOAT        COMMENT '本次会话得分 0-1（苏格拉底/Debug用）',
    hints_used      TINYINT      COMMENT '使用提示次数（苏格拉底）',
    bugs_found      TINYINT      COMMENT '找到的bug数（Debug）',
    bugs_total      TINYINT      COMMENT '总bug数（Debug）',

    -- 时间
    started_at      BIGINT       NOT NULL COMMENT 'UTC毫秒',
    last_active_at  BIGINT       NOT NULL COMMENT '最后活动时间',
    ended_at        BIGINT                COMMENT '结束时间',
    expires_at      BIGINT       NOT NULL COMMENT '过期时间（30分钟无活动）',

    INDEX idx_user_type (user_id, session_type),
    INDEX idx_problem (problem_id),
    INDEX idx_expires (expires_at)
) ENGINE=InnoDB COMMENT='交互式学习会话记录';

-- 分离消息记录（主表不存消息，方便清理）
CREATE TABLE session_messages (
    id              BIGINT       AUTO_INCREMENT PRIMARY KEY,
    session_id      VARCHAR(36)  NOT NULL,
    role            ENUM('user','ai','system') NOT NULL,
    content         TEXT         NOT NULL,
    message_type    VARCHAR(50)  COMMENT '消息子类型（hint/summary/question等）',
    metadata_json   TEXT         COMMENT '消息元数据',
    created_at      BIGINT       NOT NULL,
    INDEX idx_session (session_id, created_at)
) ENGINE=InnoDB COMMENT='会话消息记录（90天保留期）';
```

### 2.3 会话管理规则

```
会话生命周期：

ACTIVE（活跃）
  ├─ 30分钟无活动 → EXPIRED（自动）
  ├─ 用户主动结束 → COMPLETED
  ├─ 费曼达到20轮 → 自动触发总结 → COMPLETED
  └─ 苏格拉底解题成功 → 自动生成总结 → COMPLETED

PAUSED（暂停）
  ├─ 用户离开页面时 → PAUSED（前端 beforeunload）
  └─ 重新进入同题 → 提示"继续上次对话？" → 恢复 ACTIVE

EXPIRED
  └─ 不能恢复，数据保留到90天清理

断线重连（15分钟内）：
  → WebSocket 重连后携带 sessionId
  → 服务端验证 token + sessionId
  → 恢复会话上下文（最近20条消息）
  → 前端重新渲染消息历史

速率限制：
  → 单用户每秒最多 5 条消息（超过则返回 RATE_LIMIT）
```

## 三、费曼学习模式（/feynman）

### 3.1 用户旅程

```
进入方式：
1. 题目详情页 → 「用费曼法学这题」按钮
2. 直接访问 /feynman?problem={id}&level={1-5}

─────────────────────────────────────────

完整流程：

用户进入页面
  │
  ▼
检查是否有未完成的同题会话
  ├─→ 有 → 弹窗询问「继续上次对话（共 8 轮）？」
  │          [继续] [重新开始]
  │
  └─→ 无 → 新建会话，AI 发送开场白

AI 开场白（固定格式）：
  "你好！我们来用费曼学习法深入理解「{{problemTitle}}」。
   请用自己的话描述你对这题的解题思路，可以从直觉入手，
   不需要很完整，写出你能想到的部分就好。"

用户输入思路
  │
  ▼
AI 分析输入，识别：
  ├─ 理解漏洞（跳步/模糊/逻辑断裂）
  ├─ 正确的部分（给予肯定）
  └─ 需要追问的点

AI 发出追问
  │
  ▼
多轮对话（最多 20 轮）
  │
  ├─→ 第 18 轮时：系统消息提醒「还剩2轮，建议点击生成总结」
  │
  ├─→ 第 20 轮时：自动触发总结生成
  │
  └─→ 用户随时可点击「结束并生成总结」

生成结构化总结：
  ├─ 你的理解路径（按时间线）
  ├─ 核心思路（1-3句话）
  ├─ 你理解对了的部分 ✅
  ├─ 需要强化的薄弱点 ⚠️
  └─ AI 标准解法对比

总结完成 → 提示「加入复习计划」→ 结束
```

### 3.4 后端实现

```java
@Component
public class FeynmanChatHandler implements WebSocketMessageHandler {

    @Override
    public String getType() { return "FEYNMAN_CHAT"; }

    @Override
    public void handle(WebSocketSession ws, WSMessage msg) {
        String sessionId = msg.getSessionId();
        String userInput = (String) msg.getPayload().get("content");

        // 1. 加载会话上下文（最近20条消息，防止 token 超限）
        SessionContext ctx = sessionContextService.load(sessionId);
        ctx.addUserMessage(userInput);

        // 2. 检查轮次限制
        if (ctx.getRoundCount() >= 18) {
            sendSystemMessage(ws, sessionId,
                "💡 还剩 " + (20 - ctx.getRoundCount()) + " 轮对话，建议点击「生成总结」");
        }
        if (ctx.getRoundCount() >= 20) {
            triggerSummaryGeneration(ws, sessionId, ctx);
            return;
        }

        // 3. 构造 AI Prompt（包含对话历史 + 费曼分析指令）
        String prompt = buildFeynmanPrompt(ctx, userInput);

        // 4. 流式调用 AI（每个 chunk 推送到 WebSocket）
        smartRouter.routeStreaming(
            new AiRequest().setContent(prompt).setType(RequestType.FEYNMAN_ANALYSIS),
            chunk -> sendStreamChunk(ws, sessionId, chunk),
            () -> onStreamComplete(ws, sessionId, ctx)
        );

        // 5. 持久化消息
        ctx.incrementRound();
        sessionContextService.save(sessionId, ctx);
        persistMessage(sessionId, "user", userInput);
    }

    private String buildFeynmanPrompt(SessionContext ctx, String userInput) {
        return """
            你是一位费曼学习导师，正在帮助学生深度理解「%s」这道算法题。
            
            ## 对话历史
            %s
            
            ## 学生最新输入
            %s
            
            ## 你的任务
            1. 识别学生表达中的理解漏洞（跳步/模糊/逻辑断裂）
            2. 肯定正确的部分（重要！先肯定再追问）
            3. 提出一个引导性问题，帮助学生自己推导出漏洞处的正确理解
            4. 禁止直接给出答案，用问题引导
            5. 语气亲切，像一个耐心的朋友
            6. 回复控制在 100 字以内
            """.formatted(
                ctx.getProblemTitle(),
                ctx.getFormattedHistory(10),  // 最近10条
                userInput
            );
    }
}
```

    // 常见 bug 类型及其生成规则
    enum BugType {
        OFF_BY_ONE,          // 循环边界 < 改 <=，或下标差一
        BOUNDARY_MISSING,    // 遗漏边界条件检查（null/empty/single）
        CONDITION_ERROR,     // 逻辑条件写错（+ 写成 -，> 写成 >=）
        INIT_ERROR,          // 变量初始化错误（0 改 1，[] 改 {}）
        ORDER_ERROR,         // 操作顺序错误（先更新后判断 → 先判断后更新）
    }

    public DebugChallenge generate(String problemId, int bugCount) {
        // 1. 获取题目的正确解法代码
        String correctCode = solutionRepo.findBestSolution(problemId);

        // 2. 根据代码分析可以植入的 bug 位置
        List<BugInsertionPoint> points = analyzeInsertionPoints(correctCode);

        // 3. 随机选择 bugCount 个位置，植入不同类型的 bug
        List<BugInsertion> bugs = selectAndInsertBugs(points, bugCount);

        // 4. 生成触发 bug 的测试用例
        List<TestCase> triggerCases = generateTriggerCases(correctCode, bugs);

        return DebugChallenge.builder()
            .problemId(problemId)
            .buggyCode(applyBugs(correctCode, bugs))
            .bugCount(bugs.size())
            .triggerTestCases(triggerCases)
            .bugs(bugs)  // 答案（不发给前端）

    }

### 6.2 错误植入策略

```
错误难度等级：
  Easy（容易发现）: 明显的逻辑错误（+ 写成 -，算法完全错误）
  Medium（需要思考）: 边界条件错误、复杂度描述偏差
  Hard（隐蔽）: 细节描述不准确（"任意两个"写成"相邻两个"）

错误类型：
  1. 数学运算符错误：need = target + nums[i] （应为 -）
  2. 复杂度描述错误：时间复杂度 O(1) （应为 O(n)）
  3. 数据结构属性错误：哈希表查找是 O(n) （应为 O(1)）
  4. 算法描述遗漏：没有提到"先检查后存入"的顺序
  5. 边界条件错误：没有处理数组元素相同的情况

错误隐蔽度原则：
  - 错误所在的句子上下文要合理，不能明显突兀
  - 错误不能在第一段（避免用户还没看完就提交）
  - 同一段落只有一个错误
```
