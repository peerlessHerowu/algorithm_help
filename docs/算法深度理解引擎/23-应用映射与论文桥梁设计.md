## 一、产品定位

这几个模块共同解决一个问题：**让算法学习有意义感**。

```
学完"最短路径"之后的两种感受：

❌ 普通做题：「又一道面试题做完了」
✅ 有这些模块：「原来 Google Maps 导航就是这个！
                原来 PageRank 是 BFS 的变体！
                Dijkstra 1959 年在咖啡馆20分钟想出来的！」
```

## 三、数学基础关联层（M9）

### 3.1 数学关联数据表

```sql
CREATE TABLE math_concept_links (
    id              VARCHAR(36)  PRIMARY KEY,
    pattern_id      VARCHAR(50)  NOT NULL  COMMENT '关联算法模式',
    math_concept    VARCHAR(100) NOT NULL  COMMENT '数学概念名称',
    math_category   ENUM('combinatorics','linear_algebra','probability',
                         'information_theory','number_theory','calculus',
                         'graph_theory','automata') NOT NULL,
    description     TEXT COMMENT '关联说明（为什么这个算法需要这个数学）',
    level           TINYINT COMMENT '适合的理解级别（3-5）',
    reference_json  JSON COMMENT '权威引用 [{type, book, chapter, url}]',
    visualization_type ENUM('recursive_tree','dp_table','state_machine',
                            'probability_dist','matrix_transform') COMMENT '推荐可视化方式',
    INDEX idx_pattern (pattern_id)
) ENGINE=InnoDB COMMENT='算法-数学关联';
```

## 六、API 设计

```
# 应用映射
GET /api/v1/patterns/{id}/applications          → 四维应用映射
GET /api/v1/patterns/{id}/applications/{domain} → 某维度详细案例
GET /api/v1/patterns/{id}/cross-domain-table    → 跨域映射表格数据

# 数学关联
GET /api/v1/patterns/{id}/math-links            → 该模式的数学关联列表

# 论文桥梁
GET /api/v1/patterns/{id}/paper-bridges         → 该模式的论文桥梁列表
GET /api/v1/paper-bridges/{id}                  → 单个桥梁详情

# 算法考古
GET /api/v1/archaeology                         → 考古列表
GET /api/v1/archaeology/{id}                    → 单个故事详情
GET /api/v1/problems/{id}/archaeology           → 题目关联的考古故事（用于页面卡片）
```

   scripts/verify-mini-cases.py

   - 确认无语法错误和运行时错误

   - 每个 published 状态的桥梁至少有 l3_summary

   - 最后一步必须有 colab_url 或 "即将支持" 标记

4. 算法故事页面测试：
   - 访问 /archaeology/dijkstra
   - 截图：时间线可见，故事正文存在
   - 验证：story_content 字数在 500-1500 字之间
