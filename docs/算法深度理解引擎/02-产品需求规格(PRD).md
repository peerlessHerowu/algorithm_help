# 算法深度理解引擎 - 产品需求规格 (PRD)

> 文档版本：v1.0 | 更新时间：2026-06-21

## 一、产品概述

### 1.1 产品名称

算法深度理解引擎 (Algorithm Deep Understanding Engine, ADUE)

### 1.2 产品愿景

用认知科学 × AI 重新定义算法学习体验——从直觉到论文，从刷题到实践，五级深度随你选。

### 1.3 核心价值主张

不只是刷题，而是让每道算法题变成深刻、可迁移、可应用的知识。

### 1.4 目标用户

| 用户群 | 核心需求 | 使用场景 | 优先级 |
|--------|----------|----------|--------|
| 深度理解追求者 | 从本质理解、举一反三 | 长期学习 | P0 |
| 面试准备者 | 短时间深入理解核心算法 | 面试前1-3个月集中 | P0 |
| 算法初学者 | 降低理解门槛、建立直觉 | 日常学习 | P1 |
| 竞赛选手 | 模式提炼、高级技巧 | 赛前训练 | P1 |
| 算法工程师 | 工业应用映射、前沿论文 | 工作中查阅 | P2 |
| 计算机专业学生 | 课程辅助、考试准备 | 学期内使用 | P2 |

## 三、核心功能模块详细需求

### 3.1 M1: 高质量题解聚合 + AI 精炼

#### 功能描述

从各主流平台（LeetCode、Codeforces、牛客等）抓取高赞/高质量题解，通过 AI 融合精炼为最佳解释。

#### 子功能清单

| ID | 功能点 | 描述 |
|----|--------|------|
| M1.1 | 多平台题目统一映射 | LeetCode #1 = 牛客 xxx = HackerRank xxx，建立统一题目ID |
| M1.2 | 题解质量评估 | AI 评估题解质量（清晰度、完整度、正确性），筛选top解答 |
| M1.3 | 多题解融合精炼 | 将多个高质量题解的优点融合为一个"最佳解释" |
| M1.4 | 多语言代码对照 | 同一解法自动转换为 Python/Java/Go/C++ 四种语言 |
| M1.5 | 时间/空间复杂度深度分析 | 不只写O(n)，解释"为什么是O(n)"、推导过程 |
| M1.6 | 解法适用场景标注 | 每种解法标注：适合什么数据规模、什么面试场景 |
| M1.7 | 错误检测与纠正 | AI 审校题解中的逻辑错误、边界遗漏、不准确说法 |
| M1.8 | 自然语言口述版 | 生成面试时"边想边说"的口述版本 |

#### 输入/输出

- **输入**：题目编号/链接/题目描述
- **输出**：结构化的精炼题解，包含：题目理解→思路分析→多种解法→代码→复杂度→总结

#### 非功能需求

- 单题解析生成时间 < 30s（缓存命中 < 1s）
- 支持离线预生成，在线按需加载
- 解析准确率 > 95%（对比人工审核）

### 3.2 M2: AI 流程解析引擎

#### 功能描述

用具体例子，一步步走完算法的执行流程，覆盖标准场景和边界场景，让用户"亲眼看到"算法是如何工作的。

#### 子功能清单

| ID | 功能点 | 描述 |
|----|--------|------|
| M2.1 | 标准例子逐步演示 | 用最简单的输入走一遍完整流程，建立直觉 |
| M2.2 | 边界场景覆盖 | 空输入、单元素、最大值、重复元素、全相同等 |
| M2.3 | 反例展示 | 为什么贪心不行？为什么暴力超时？展示错误思路的后果 |
| M2.4 | "如果不这样做会怎样" | 对比正确做法和错误做法的执行结果差异 |
| M2.5 | 变量状态追踪表 | 每一步的变量值、指针位置、数据结构状态表格 |
| M2.6 | 关键决策点高亮 | 标注"这里是关键决策"、"大多数人会犯错的地方" |
| M2.7 | 递归调用栈展开 | 对递归算法展示完整的调用栈和返回过程 |
| M2.8 | 自定义输入运行 | 用户可以输入自己的测试数据，看完整执行过程 |

#### 场景覆盖策略

```
标准例子：建立基本直觉（必选）
  ↓
边界例子：验证理解（必选）
  ↓
反例/错误思路：加深理解（推荐）
  ↓
大规模数据：理解复杂度（可选）
  ↓
自定义输入：验证掌握（交互式）
```

### 3.3 M3: 智能图解系统

#### 功能描述

根据算法类型自动选择最合适的图表类型，生成清晰的可视化图解。图对于人类理解最深刻、最容易理解。

#### 图类型自动匹配规则

| 算法类型 | 推荐图类型 | 说明 |
|----------|-----------|------|
| 数组/双指针 | 指针移动动画、区间着色图 | 用颜色和箭头标注指针位置和移动方向 |
| 链表 | 节点连线图、指针跳转动画 | 节点方框+箭头，操作前后对比 |
| 树 | 树形结构图、递归调用栈 | 节点着色表示访问状态 |
| 图论 | 节点边图、BFS/DFS着色过程 | 逐步着色，标注发现/完成时间 |
| 动态规划 | DP表格填充动画、状态转移箭头图 | 高亮当前填充格和依赖格 |
| 回溯 | 决策树、剪枝可视化 | 灰色表示被剪枝的分支 |
| 排序 | 条形图交换动画 | 经典的高度对比动画 |
| 滑动窗口 | 窗口移动动画、窗口内元素高亮 | 左右边界用颜色标注 |
| 堆 | 完全二叉树 + 数组对应图 | 树和数组并排显示 |
| 字符串匹配 | 字符对齐图、状态机图 | KMP的next数组可视化 |
| 并查集 | 森林图、路径压缩前后对比 | 压缩前后树高度对比 |
| 二分搜索 | 区间收缩动画 | 每步缩小的搜索范围高亮 |

#### 技术实现选型

| 方案 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| Mermaid | 文本生成、易集成、AI友好 | 表达力有限 | 流程图、树、简单图 |
| D3.js | 高度可定制、交互式 | 开发成本高 | 复杂动画、交互式 |
| SVG (AI生成) | 灵活、可嵌入 | 复杂场景难生成 | 静态图解 |
| Manim | 高质量数学动画 | 需要Python环境 | 数学推导动画 |
| Canvas/WebGL | 高性能动画 | 开发复杂 | 大规模数据可视化 |

**MVP推荐**：Mermaid（静态图）+ 简单SVG/Canvas（动画）

### 3.4 M4: 多解法对比与底层框架提炼

#### 功能描述

同一题目的多种解法不仅要展示，更要揭示它们之间的演进关系、共同本质、底层共同框架。

#### 子功能清单

| ID | 功能点 | 描述 |
|----|--------|------|
| M4.1 | 解法演进关系图 | 从暴力到最优的优化路径，标注"为什么优化"和"怎么想到的" |
| M4.2 | 多维对比矩阵 | 时间/空间/代码复杂度/适用场景/面试推荐度 |
| M4.3 | 底层共同思路提炼 | 抽象出各解法的共同本质（如"两数之和"本质是"查找互补元素"） |
| M4.4 | 解法适用条件分析 | 每种解法在什么条件下最优、什么条件下退化 |
| M4.5 | 共同框架图解 | 用图展示各解法如何映射到同一个抽象框架 |
| M4.6 | 思路迁移路径 | 这个框架可以推广到哪些其他题目 |

#### 解法拓扑图示例

```
暴力枚举 O(n²)
  │
  ├─→ 优化方向1：减少重复计算
  │     └─→ 哈希表 O(n)
  │
  └─→ 优化方向2：排序后利用有序性
        └─→ 排序+双指针 O(n log n)

共同底层思路：本质都是"在集合中寻找配对元素"
框架迁移：→ 3Sum → 4Sum → 子数组和 → 两数之差
```

### 3.5 M5: 分级解释系统(5级)

#### 功能描述

同一知识点提供五个级别的解释，适配从零基础到研究者的不同认知层次。基于维果茨基的"最近发展区"理论和认知负荷理论设计。

#### 五级定义

| 级别 | 代号 | 用户画像 | 认知特征 | 解释风格 |
|------|------|----------|----------|----------|
| L1 | 直觉级 | 零基础/跨行业 | 无抽象思维基础 | 纯生活类比，零代码，故事化 |
| L2 | 入门级 | 刚学编程1年内 | 能理解基本语法 | 具体例子+伪代码+大量图 |
| L3 | 进阶级 | 学算法1-3年 | 能套模板但不灵活 | 模式框架+变体对比+代码 |
| L4 | 熟练级 | 3-5年/工程师 | 关注工程实践 | 边界分析+优化+复杂度证明 |
| L5 | 专家级 | 研究者/资深 | 关注理论边界 | 论文原文+数学推导+前沿 |

#### 每级包含的解释方法组合

| 方法 | L1 | L2 | L3 | L4 | L5 |
|------|----|----|----|----|-----|
| 生活类比 | ★★★ | ★★☆ | ★☆☆ | - | - |
| 动画可视化 | ★★★ | ★★★ | ★★☆ | ★☆☆ | - |
| 代码追踪 | - | ★★★ | ★★☆ | ★☆☆ | - |
| 模式模板 | - | ★☆☆ | ★★★ | ★★★ | ★☆☆ |
| 数学推导 | - | - | ★☆☆ | ★★☆ | ★★★ |
| 论文引用 | - | - | - | ★☆☆ | ★★★ |
| 苏格拉底追问 | ★☆☆ | ★★☆ | ★★★ | ★★☆ | ★☆☆ |
| 跨域迁移 | ★☆☆ | ★☆☆ | ★★☆ | ★★★ | ★★★ |

#### 用户级别自动判定

- 初始：用户自选级别
- 后续：基于用户的答题表现、阅读行为自动调整
- 随时可手动切换级别

### 3.6 M6: 用户思路转化(费曼模式)

#### 功能描述

支持用户输入自己的解题思路（文字/语音），AI 识别理解漏洞、引导追问、最终生成结构化的高质量解释。也支持粘贴链接、导入别人的题解进行解析和优化。

#### 子功能清单

| ID | 功能点 | 描述 |
|----|--------|------|
| M6.1 | 文字思路输入 | 用户用自己的话讲解思路，支持 Markdown |
| M6.2 | 语音思路输入 | 语音转文字后进入同一流程（后期） |
| M6.3 | AI 理解漏洞识别 | 检测用户描述中的跳步、模糊点、逻辑断裂 |
| M6.4 | 引导式追问 | "你说的'然后排序'，排序依据是什么？" |
| M6.5 | 结构化输出生成 | 直觉→思路→伪代码→正式代码→复杂度分析 |
| M6.6 | 链接粘贴解析 | 粘贴题解URL，自动抓取正文/图片/评论 |
| M6.7 | 图片/动图保留 | 解析内容中的图片和GIF，保留并标注 |
| M6.8 | 评论精华提取 | 提取题解下的优质评论（纠错/补充/类比） |
| M6.9 | AI 错误检测 | 对导入的题解进行正确性审查，标注错误 |
| M6.10 | 多类比生成 | 同一思路用多个不同类比解释，用户选最 click 的 |

#### 链接解析技术可行性

### 3.7 M7: 模式提炼 + 知识图谱

#### 功能描述

从多道题目中提炼出共同模式，建立题目间的关联关系图谱，实现跨题目的知识迁移。

#### 子功能清单

| ID | 功能点 | 描述 |
|----|--------|------|
| M7.1 | 算法模式卡片 | 每个模式一张卡：模板代码+适用信号+常见变体 |
| M7.2 | 题目关联图谱 | 可视化题目间关系（前置题→本题→进阶题） |
| M7.3 | "做了这题还应做"推荐 | 基于模式相似度推荐下一题 |
| M7.4 | 模式识别训练 | 给题目描述，判断该用什么模式（不写代码） |
| M7.5 | 模式演进路径 | 从基础模式到高级变体的学习路径 |
| M7.6 | 跨领域模式映射 | 同一模式在不同领域的应用对比 |

#### 核心模式分类体系

```
├── 双指针 (Two Pointers)
│   ├── 对撞指针
│   ├── 快慢指针
│   └── 滑动窗口
├── 二分搜索 (Binary Search)
│   ├── 标准二分
│   ├── 左边界二分
│   └── 右边界二分
├── 动态规划 (DP)
│   ├── 线性DP
│   ├── 区间DP
│   ├── 树形DP
│   ├── 状压DP
│   └── 数位DP
├── 图论 (Graph)
│   ├── BFS / DFS
│   ├── 最短路
│   ├── 拓扑排序
│   └── 最小生成树
├── 回溯 (Backtracking)
│   ├── 排列/组合/子集
│   ├── 棋盘类
│   └── 剪枝优化
├── 贪心 (Greedy)
├── 分治 (Divide & Conquer)
├── 单调栈/单调队列
├── 并查集 (Union-Find)
├── 字符串 (String)
│   ├── KMP / Rabin-Karp
│   ├── Trie
│   └── 后缀数组
└── 高级数据结构
    ├── 线段树
    ├── 树状数组
    └── 平衡BST
```

### 3.8 M8: 实际应用映射

#### 功能描述

将算法与真实世界的工程应用、AI前沿、工作场景、人生决策建立映射关系，让学习不止于刷题。

#### 应用映射维度

| 算法 | 工业应用 | AI/ML应用 | 工作映射 | 人生映射 |
|------|----------|-----------|----------|----------|
| 图最短路径 | 导航系统、网络路由 | 机器人路径规划 | 项目最短路径 | 达成目标的最优路径 |
| 动态规划 | 资源调度、编译优化 | NLP序列对齐、强化学习 | 拆解复杂任务 | 复杂决策分步走 |
| 树/Trie | 搜索引擎补全、文件系统 | DNA序列匹配 | 知识体系构建 | 层级化思考 |
| 并查集 | 社交网络连通性 | 图像分割 | 团队合并管理 | 人际关系网络 |
| 滑动窗口 | 网络流量监控 | 实时数据分析 | 时间管理窗口 | 专注力管理 |
| 堆/优先队列 | OS调度、推荐排序 | 推荐系统 | 任务优先级 | 精力分配 |
| 回溯 | 约束求解 | 自动驾驶决策 | 试错后回退 | 及时止损 |
| BFS/DFS | 爬虫、编译器 | 游戏AI、知识图谱 | 广度探索vs深度钻研 | 社交拓展 |
| 贪心 | 任务调度 | 特征选择 | 快速决策 | 局部最优陷阱 |
| 分治 | MapReduce | 分布式训练 | 大项目分解 | 多人协作 |

#### "迷你案例"设计

每个应用映射不只列出场景，还给出一个可运行的"迷你案例"：
- 用 Dijkstra 实现简化版地图导航
- 用 Trie 实现搜索框自动补全
- 用优先队列实现任务调度器
- 用 BFS 实现网页爬虫的链接发现

### 3.9 M9: 数学基础关联层

#### 功能描述

算法背后的数学知识，同样用举例子走流程、画图解析、分级别的方式讲解。关联权威文章、论文、书籍（精确到章节）。

#### 算法-数学关联表

| 算法领域 | 相关数学 | 可视化方式 | 权威参考 |
|----------|----------|-----------|----------|
| 动态规划 | 递推关系、组合数学 | 递推公式动画+数列展开 | CLRS第15章、具体数学第7章 |
| 图论 | 线性代数（邻接矩阵）、概率 | 矩阵变换可视化 | CLRS第22-26章 |
| 排序下界 | 信息论（比较下界 log(n!)） | 决策树展开图 | CLRS第8章定理8.1 |
| 分治 | 主定理 Master Theorem | 递归树画图 | CLRS第4章 |
| 随机算法 | 概率论、期望 | 蒙特卡洛模拟动画 | CLRS第5章 |
| 字符串 | 有限自动机、正则表达式 | 状态机图 | CLRS第32章 |
| NP完全 | 计算复杂性理论 | 归约关系图 | CLRS第34章 |
| 近似算法 | 近似比证明 | 最优解对比图 | CLRS第35章 |

#### 数学讲解原则

1. **同样分五级**：L1用直觉类比，L5用严格证明
2. **举例先行**：先用具体数字走一遍，再抽象为公式
3. **图解优先**：能画图的一定画图（递归树、状态转移图、概率分布图）
4. **权威溯源**：每个数学概念标注出处（书名+章节+页码）
5. **"为什么需要这个数学"**：先解释动机，再讲内容

|------|----------|
| 教材 | "详见 CLRS 第15章 §15.3 动态规划的要素, p.379" |
| 论文 | "Dijkstra, E.W. (1959) A note on two problems in connexion with graphs" |
| 课程 | "MIT 6.006 Lecture 15: Dynamic Programming" |

### 3.10 M10: AI前沿/论文桥梁

#### 功能描述

设计"从LeetCode到Paper"的学习路径，让基础算法与AI前沿应用之间有平滑过渡。

#### 桥梁路径示例

```
基础算法（如 BFS）
  → 图神经网络中的变体（消息传递机制）
    → 具体论文：GraphSAGE (Hamilton et al., 2017)
      → 实际应用：社交网络推荐系统
        → 动手实验：用 PyTorch Geometric 实现简化版
```

```
基础算法（如 动态规划）
  → 强化学习中的 Value Iteration
    → 具体论文：DQN (Mnih et al., 2015)
      → 实际应用：游戏AI、机器人控制
        → 动手实验：用 OpenAI Gym 实现简单RL
```

| 领域 | 相关基础算法 | 前沿应用 |

#### 论文解读分级

- **L3 进阶级**：论文核心思想的通俗解释 + 与基础算法的联系
- **L4 熟练级**：论文方法的详细解读 + 代码实现 + 实验复现

### 3.13 M13: 更多独特功能模块

#### 算法考古（发明故事）

让算法有温度——讲述算法的发明故事、历史背景、设计动机：
- Dijkstra 在咖啡馆20分钟想出最短路算法
- Huffman 编码是研究生期末作业
- RSA 在酒会上灵感迸发
- PageRank 源于学术引用网络

**价值**：知道"为什么发明"比知道"怎么用"更容易记住。

#### 算法Debug训练

- 给一段有 bug 的代码，让用户找错
- AI 自动生成各种常见 bug 变体
- 比"看正确代码"学习效果更好（主动学习 vs 被动阅读）

#### 逆向思维训练

- 给算法的输出，推断输入或过程
- 给时间复杂度要求，设计满足它的解法
- 练习"从约束倒推方法"的能力

#### 算法思维日记

- 每天记录"今天在工作中用到了什么算法思维"
- AI 帮助识别：设计数据库索引时其实在用 B-Tree 思想
- 建立"算法不是面试专用，而是思维工具"的认知

#### 多平台题目统一ID映射

- LeetCode #1 = 牛客 NC01 = HackerRank two-sum
- 用户在任何平台做过的题都能统一管理
- 支持导入各平台的做题记录

#### 离线导出

- 生成的精炼笔记可导出为 PDF / Notion / Markdown
- 支持整本"个人算法笔记"导出
- 适合打印复习、离线阅读

#### 竞赛回顾模式

- 对 LeetCode 周赛/月赛题做赛后深度分析
- 分析出题趋势、高频模式
- 适合竞赛选手赛后复盘

## 五、约束与假设

### 5.1 技术约束

- 前期无 AI API Key，依赖 Kiro CLI 或本地模型
- 数据来源涉及爬虫，需注意平台 ToS 和法律风险
- 图片/动图解析依赖多模态 AI 能力

### 5.2 商业约束

- 前期为个人项目，无商业化压力
- 设计上预留商业化能力（用户系统、付费层级）
- AI 成本需要严格控制

### 5.3 假设

- 用户有基本的编程基础（至少能看懂代码）
- 用户愿意花时间"深度理解"而非只要答案
- AI 技术在未来会持续降本增效
- 内容质量 > 内容数量
