## 二、逐页面/逐功能 Review（产品+用户视角）

### 2.1 首页（scheme-a.html #home + #dashboard）

**✅ 做得好的点：**
- 匿名用户 Hero + 已登录 Dashboard 双模式设计，逻辑清晰
- Dashboard 三卡片（今日计划/待复习/连续天数）信息密度适中
- "继续学习"卡片保留上下文（上次阅读到哪里），体验连贯
- 基于薄弱模式的推荐，个性化价值明确

**⚠️ 需要补充/优化的点：**
1. **首次登录但无数据时的空状态**：新注册用户 Dashboard 应该展示"快速上手"引导，而非空的推荐列表
2. **Dashboard 推荐区与"热门题目"区的关系**：已登录时是否还展示"热门题目"？建议已登录用户隐藏热门区域，仅展示个性化推荐


### 2.2 题目列表页（scheme-a.html #problems）

**✅ 做得好的点：**
- 搜索+筛选+排序三合一，操作栏清晰不杂乱
- 难度/标签/公司三维筛选覆盖核心场景
- 生成状态可视化（绿点已生成/黄点生成中/灰点待生成）直观
- 空状态有友好提示

**⚠️ 需要补充/优化的点：**
1. **公司标签筛选**：UI 中用 `<select>` 下拉，但公司标签是多选场景（面试者可能同时选 Google+Meta），建议改为多选 chip 或多选下拉
2. **"已生成/未生成"筛选**：Spec R9.1 定义了 `status=GENERATED/NOT_GENERATED/ALL` 参数，但 UI 筛选标签中没有明确展示这个维度的切换入口。建议在筛选行增加"已生成/全部"切换
3. **列表项点击区域**：整行可点击但没有 hover 效果预览，可考虑 hover 时在右侧预览题目摘要（类似 Linear 的 issue 预览）
4. **结果计数**：UI 没有展示"共 X 条结果"，当筛选有效时用户不知道匹配了多少

### 2.3 题目详情页（scheme-a.html #problem-detail）

**✅ 做得好的点：**
- LevelTabs 设计精致（图标+名称+L5锁定态）
- 多平台链接展示（LeetCode/力扣/牛客）解决跨平台用户痛点
- 解法演进关系图 + 底层共同框架提炼，超越传统题解站
- "下一步"行动引导区域设计周到（费曼/面试/变体题/复习计划四选项）
- 内容反馈组件位置合理（页底）
- TOC 右侧目录有滚动高亮

**⚠️ 需要补充/优化的点：**
1. **版本信息入口不够明显**："v2 · 查看历史版本"文字太小且位于信息头右下角，可能被忽略。建议改为更明确的"内容版本 v2 ↗"链接
2. **级别切换时的 loading 态**：UI 只展示了内容和空状态，缺少"切换级别后内容加载中"的骨架屏过渡态
3. **代码块语言缺少 TypeScript/Rust**：Spec R1 定义 defaultLanguage 仅 4 种（Python/Java/Go/C++），但 UI CodeBlock Tab 中多了 TypeScript。需确认 Spec 是否扩展支持 TS/Rust，或 UI 去掉
4. **Mermaid 图解的图注缺失**：图解区域下方没有图注说明（如"示例：nums=[2,7,11,15], target=9"），新用户可能不理解图解对应哪个输入


### 2.4 费曼模式（scheme-a.html #feynman）

**✅ 做得好的点：**
- 左右分栏（对话区+评估面板）信息布局合理
- 理解评估面板实时标注"已掌握/部分/未涉及"，给用户即时反馈
- 多类比选择面板（字典/拼图/超市）让用户找到最 click 的理解方式
- 历史会话列表支持恢复之前的对话
- AI 回复中有"✓ 完全正确！"等正向激励

**⚠️ 需要补充/优化的点：**
1. **结束会话后的结构化总结展示**：Spec R1.4 要求结束时生成"直觉→思路→伪代码→代码→复杂度"结构化输出，但 UI 中仅有一个"✅ 结束并生成总结"按钮，缺少总结页面的完整 UI（总结面板+各段折叠展开+保存/导出按钮）
2. **"未涉及"知识点的引导**：Spec 3 R12.8 要求未涉及项提供"💡 引导这个话题"按钮，当前 UI 评估面板只显示状态没有操作入口
3. **对话轮次限制提示**：Spec R8.3 限制 20 轮对话，UI 应在接近上限时（如第 18 轮）提示"还剩 2 轮对话，建议总结"

### 2.5 面试模拟（scheme-a.html #interview）

**✅ 做得好的点：**
- 面试前配置面板（难度/时长/公司风格/指定题目）完整覆盖 Spec R15
- 计时器显示突出（固定位置、等宽字体、Warning 颜色）
- 代码编辑区独立在右侧，模拟真实面试双区域
- 评分报告雷达图 + 详细分数条形图双展示

**⚠️ 需要补充/优化的点：**
1. **Follow-up 变体题展示**：supplement-v2 #interview-v2 中有 Follow-up 追问展示，但与主面试页面的关系不清晰——这些追问应该在面试对话流中自然出现，而非独立区域
2. **白板模式切换**：supplement-v2 有白板模式 Toggle，但主面试页代码区默认是有高亮的。建议在面试配置面板中增加"白板模式"选项（开始前勾选）
3. **面试历史趋势入口**：Spec R3.7 要求"查看评分趋势折线图"，当前 UI 评分报告中没有"查看历史趋势"的跳转链接
4. **沟通反馈的展示时机**：supplement-v2 有沟通能力实时反馈 UI，但这应该是面试过程中嵌入的（非独立页面）。建议在面试对话区左下角实时展示沟通提示气泡
5. **低分维度改进建议**：Spec R3.5 要求"低分维度(<7分)附带具体改进建议"，当前雷达图只展示分数没有建议文字


### 2.6 复习中心（scheme-a.html #review）

**✅ 做得好的点：**
- 今日计划卡片突出（蓝色边框+CTA按钮），第一视觉焦点正确
- 多复习方式选择器（翻卡/看图猜/补全代码/模式Quiz/复杂度）丰富
- 翻卡片正面/背面展示清晰，自评按钮（忘了/模糊/记得/秒杀）色彩编码直观
- 学习趋势柱状图给予用户成就感

**⚠️ 需要补充/优化的点：**
1. **自评按钮缺少间隔预告**：Spec 3 R25.7 要求 hover 时展示 tooltip "忘了(明天)/模糊(3天后)/记得(7天后)/秒杀(14天后)"，当前 UI 只有按钮文字没有间隔提示
2. **复习完成后的正向激励**：Spec 3 R25.6 要求完成后展示"太棒了！🎉"弹窗含数据总结，当前 UI 无此设计
3. **"补全代码"和"看图猜模式"方式没有对应的 UI 页面**：仅有按钮入口，缺少实际交互页面原型

### 2.7 设置页（scheme-a.html #settings + supplement-v2 #settings-v2）

**✅ 做得好的点：**
- 核心三项（级别/语言/主题）简洁明确
- 通知设置细化到每个类型（生成完成/复习提醒/系统公告/飘屏）
- 数据导出+账户删除放在"危险区域"，有警示设计
- "学习水平自测"入口（5题快测推荐级别）是亮点

**⚠️ 需要补充/优化的点：**
1. **缺少"复习提醒时间"设置**：Spec R17 定义偏好含 notificationSettings，但 UI 没有让用户设置"每天几点推送复习提醒"
2. **密码修改入口缺失**：设置页应有"修改密码"入口（已登录用户）
3. **语言设置的 Rust/TypeScript**：UI 中列出了 Rust 和 TS，但 Spec 仅定义 Python/Java/Go/C++ 四种。需对齐
4. **代码行号开关/动画效果开关**：UI 有但 Spec UserPreference 实体未定义这些字段，需补充到 Spec


### 2.8 苏格拉底追问（supplement #socratic）

**✅ 做得好的点：**
- 渐进式提示进度面板（4步从方向→完整代码），用户清楚自己在哪
- "⏹ 停止提示，让我想想"按钮尊重用户自主权
- 推导完成后"你的路径 vs 标准解法"双栏对比是亮点
- 差异点标注明确（"你独立推导出 O(n²)，标准思路的 O(n log n) 优化是进阶内容"）

**⚠️ 需要补充/优化的点：**
1. **提示级别与题目难度的关系不明确**：用户不知道自己用了几个 Hint 意味着什么，建议加得分/评级（如"在 Hint 2 时解出 = 优秀"）
2. **退出中途的记录保存**：如果用户在 Hint 2 后退出，下次回来是否能继续？UI 没有体现"暂停/恢复"概念

### 2.9 Debug 训练（supplement #debug）

**✅ 做得好的点：**
- 代码行号+红色下划线标注 bug 位置直观
- 测试用例区域清晰标注哪个用例触发了 bug
- Bug 标注输入区支持逐条填写
- 表现统计（正确率+薄弱类型）即时反馈

**⚠️ 需要补充/优化的点：**
1. **Bug 类型选择**：用户标注 bug 时只能写"第X行应改为XX"，缺少 bug 类型标签选择（off-by-one/边界/条件/初始化），可帮助用户认知 bug 分类
2. **难度调节入口**：UI 没有展示 Debug 题目的难度选择（Spec 说含 1-3 个 bug），用户应能选择"只包含 1 个 bug"（入门）或"3 个 bug"（挑战）

## 五、用户流程顺畅度评估

### 5.1 核心用户旅程 — 匿名→注册→学习→复习

```
匿名访问首页 → 浏览题目列表 → 查看题目详情(L3) → 切换级别 → 点击"费曼模式"
→ 弹出登录提示 → 注册/登录 → 自动跳转费曼页 → 完成对话 → 生成总结
→ [?] 转为题解发布 → 加入复习计划 → 次日收到复习提醒 → 打开复习中心 → 翻卡复习
```

**流程断点分析：**
- ✅ 匿名→详情→需认证操作：有登录弹窗，流程顺畅
- ⚠️ 费曼结束→转为题解：data-mgmt 有"费曼转题解"完整 UI，但从费曼页到转化页的跳转入口不明确。建议在费曼总结页增加"📝 转为我的题解"CTA
- ⚠️ 注册后首次体验：新用户注册后 Dashboard 可能是空白（没有学习数据、没有推荐），需要"快速上手"引导

### 5.2 面试准备者旅程

```
首页 → 按公司筛选(Google) → 选题 → 查看L4解析 → 面试模拟入口
→ 配置(Medium/45min/Google风格) → 开始面试 → 答题+追问+写代码
→ 面试结束 → 查看评分 → [?] 查看薄弱项建议 → 针对性练习
```

**流程断点分析：**
- ⚠️ 评分报告→薄弱项训练：报告只展示分数，缺少"针对薄弱项开始训练"的直接跳转。建议在低分项下方加"💪 训练这个维度"按钮
- ⚠️ 面试后→复习：面试中做的题应自动加入复习计划，但这个自动化在 UI 中没有提示


### 5.3 内容管理者旅程

```
管理后台 → 触发 LeetCode 采集 → 查看任务进度 → 采集完成
→ 审核队列出现新内容 → 点击审核 → [?] 查看完整内容+校验报告
→ 通过/驳回 → 前端对应题目可见/不可见
```

**流程断点分析：**
- ⚠️ 审核详情页缺失：点击"审核"后应看到完整生成内容+AI校验报告+错误标注，当前只能在列表层面操作
- ✅ 采集→标准化→AI加工→审核队列：逻辑自洽，事件驱动解耦合理

## 六、设计原则评估

### 6.1 信息架构

| 维度 | 评分 | 说明 |
|------|------|------|
| 页面层级 | ⭐⭐⭐⭐⭐ | 首页→列表→详情→交互，层级清晰不超过3层 |
| 导航可达性 | ⭐⭐⭐⭐ | ⌘K 搜索 + 顶部导航 + 右侧 TOC，多路径可达 |
| 功能发现性 | ⭐⭐⭐⭐ | 费曼/面试/复习在多个位置有入口（详情页、导航栏） |
| 认知负荷 | ⭐⭐⭐⭐ | 渐进式展示，不一次性暴露所有功能 |

### 6.2 视觉设计

| 维度 | 评分 | 说明 |
|------|------|------|
| 一致性 | ⭐⭐⭐⭐⭐ | CSS 变量统一、组件风格一致、间距有规律 |
| 对比与层级 | ⭐⭐⭐⭐⭐ | 背景5级灰度、文字3级、边框3级，层次分明 |
| 色彩克制 | ⭐⭐⭐⭐⭐ | 单一强调色(蓝)+难度色+语义色，没有花哨渐变 |
| 动效预期 | ⭐⭐⭐⭐ | 设计规范有详细动效定义，UI 原型无法体现但设计稿到位 |
| 暗色执行力 | ⭐⭐⭐⭐⭐ | 近纯黑底色+低对比边框+accent glow，高级感十足 |

## 七、让人"眼前一亮"的设计亮点

1. **五级认知 LevelTabs**：这是最大的产品差异化。比任何竞品都更尊重用户的认知水平差异
2. **解法演进关系图 + 底层框架提炼**：超越"给答案"，展示"答案是怎么想到的"
3. **费曼模式理解评估面板**：实时标注掌握程度，比"AI 说你对了"更有说服力
4. **跨域迁移映射表**：DP memo = Redis 缓存的类比，让算法走出面试进入工作
5. **反向费曼法**：AI 故意讲错让用户纠正，这种"主动纠错"学习法在竞品中独一无二
6. **全服飘屏成就系统**：社区感+轻竞争驱动力，比单纯打卡更有温度
7. **算法考古（发明故事）**：Dijkstra 咖啡馆20分钟设计最短路——让算法有温度、更好记
8. **论文桥梁路径**：BFS → GraphSAGE 的渐进路径，让研究者觉得这不是刷题工具

## 十、总结与优先级建议

UI 设计已非常完善，覆盖了 Spec 中 95%+ 的用户可见功能。设计风格统一、交互逻辑自洽、信息层级清晰。对于一个算法学习产品来说，五级认知系统+跨域迁移映射+反向费曼法+算法考古这些特色功能的 UI 设计在竞品中找不到对标，确实让人"眼前一亮"。
