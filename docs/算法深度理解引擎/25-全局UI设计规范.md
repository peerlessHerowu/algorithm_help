# 25 — 全局 UI 设计规范

> 版本：v1.0 | 2026-09-01
> 适用范围：所有前端页面，基于 Next.js 14 + Tailwind CSS 3 技术栈

---

## 一、设计哲学

### 1.1 核心原则（不妥协）

```
1. 清晰 > 美观
   当两者冲突时，优先保证内容清晰、层次分明。
   美观是在清晰基础上的加分项，不是装饰目的。

2. 结构感 > 平铺
   用视觉层次引导视线：大标题 → 区块 → 内容 → 细节。
   禁止所有东西同一字号/同一权重排列。

3. 动效服务功能
   动效必须有意义（反馈状态变化、引导注意力、表达层级关系）。
   禁止纯装饰性动效（不传达信息的闪烁/旋转）。

4. 内容为王
   UI 是内容的容器，不应喧宾夺主。
   用足够的留白让内容呼吸。

5. 一致性 > 独特性
   页面间保持视觉一致，降低用户的认知负担。
```

### 1.2 算法引擎的气质

参考：Linear（现代技术感）+ Notion（安静专注）+ 3Blue1Brown（数学美感）

```
不是：花哨、炫技、游戏化过度
而是：克制、精准、有深度感

配色倾向：深邃蓝 + 白 + 极少量强调色（不超过 2 种）
字体倾向：等线体 + 适量 serif（数学公式/引用）
空间倾向：宽裕 padding，不局促
```

## 四、间距系统

### 4.1 核心间距规则

```
页面内容最大宽度：max-w-4xl（896px）居中
页面水平 padding：px-4 (手机) / px-6 (平板) / px-8 (桌面)

模块间间距（垂直）：space-y-6 (1.5rem = 24px)
卡片内 padding：p-4 (1rem) / p-5 (1.25rem，重要内容)
表单元素间距：space-y-4 (1rem = 16px)

标题距内容：mb-3 (0.75rem)
段落间距：mb-4 (1rem)

图标与文字间距：gap-2 (0.5rem)
按钮内 padding：px-4 py-2 (小) / px-5 py-2.5 (中) / px-6 py-3 (大)
```

### 4.2 留白哲学

```
宁可留白多，不要局促

卡片 padding 不低于 p-4（16px）
重要区域之间间距不低于 gap-4（16px）
正文行高不低于 leading-relaxed（1.625）

禁止：紧贴边缘的文字（必须有 padding）
禁止：连续多个元素之间没有任何间距
```

## 六、动效规范

### 6.1 已定义动画（tailwind.config.ts）

| 动画名 | 时长 | 用途 |
|--------|------|------|
| `animate-fade-in` | 150ms | 弹窗/下拉菜单出现 |
| `animate-fade-in-up` | 250ms | 卡片/内容区域出现 |
| `animate-scale-in` | 200ms | 成就弹窗、确认对话框 |
| `animate-slide-in-right` | 250ms | 侧边通知、飘屏 |
| `animate-shimmer` | 1.5s∞ | 骨架屏加载 |
| `animate-bounce-subtle` | 2s∞ | 成就图标强调 |
| `animate-spin-slow` | 3s∞ | 加载旋转（轻量） |
| `animate-typing-cursor` | 1s∞ | AI 流式输出光标 |

### 6.2 交互动效标准

```
hover：
  色彩变化：transition-colors duration-150
  阴影变化：transition-shadow duration-200
  位移效果（慎用）：transform duration-200

focus：
  强制显示 focus ring（focus-visible:ring-2）
  颜色与功能区的主色一致

active（按下）：
  scale-[0.98] duration-75（subtle 压感）

页面过渡：
  进入：animate-fade-in-up
  退出：不做动效（过于复杂）
```

### 6.3 禁止的动效

```
❌ 纯装饰旋转（不传达信息）
❌ 过长的动效（> 400ms 的普通操作）
❌ 连续动效堆砌（同一区域同时 3+ 个动效）
❌ hover 位移超过 4px（容易造成操作困难）
❌ 无障碍：prefers-reduced-motion 时必须禁用所有非必要动效
```

```css
/* 必须添加 */
@media (prefers-reduced-motion: reduce) {
  *, ::before, ::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

```
┌──────────────────────────────────────────────────────────────────┐

│  max-w-4xl mx-auto px-4 sm:px-6 lg:px-8                        │

│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

### 7.2 NavBar 规范

```
高度：h-14（56px）
背景：bg-white/80 dark:bg-gray-950/80
模糊：backdrop-blur-sm
边框：border-b border-gray-200 dark:border-gray-800
层级：z-40

内容：
  左：Logo + 主导航（桌面）/ 汉堡菜单（手机）
  右：搜索 + 主题切换 + 用户头像

主导航项：
  题目、模式、图谱、训练、复习
  激活态：text-primary-600 + 底部 2px border
  非激活：text-gray-600 hover:text-gray-900
```

### 7.3 响应式断点规则

```
手机（< 640px）：
  单列布局
  隐藏次要信息（显示精简版）
  所有弹窗改为底部 sheet
  图谱不显示（改为模式列表替代）

平板（640px - 1024px）：
  部分双列布局
  折叠侧边栏

桌面（> 1024px）：
  完整布局
  侧边面板可展开
```

## 八、图标与图形规范

### 8.1 图标使用

```
图标库：不引入额外图标库，使用 emoji + 自定义 SVG
原则：
  emoji 用于轻量标识（成就/状态/情感）
  SVG 用于需要精确控制的 UI 图标（导航/操作按钮）

禁止：混用多个图标库（风格不统一）
禁止：随意放大/缩小导致失真
```

### 8.2 难度标识

```
Easy:   🟢 或 • 绿色圆点
Medium: 🟡 或 • 黄色圆点
Hard:   🔴 或 • 红色圆点

禁止用"简单/中等/困难"文字（太占空间）
禁止用数字1/2/3（不直观）
```

## 九、交互规范

### 9.1 空状态设计

```
每个列表页面/查询场景必须有空状态设计：

┌─────────────────────────────┐
│                             │
│         🔍                  │ ← 语义图标
│                             │
│     没有找到相关题目         │ ← 简洁说明
│                             │
│   试试修改搜索条件           │ ← 操作建议
│   或 [浏览全部题目]          │ ← 可选操作
│                             │
└─────────────────────────────┘
```

### 9.2 加载状态层级

```
快速操作（< 300ms 预期）：
  不显示 loading 状态（避免闪烁）

普通请求（300ms - 2s）：
  Skeleton 骨架屏（保持布局稳定）

AI 生成（2s - 60s）：
  进度提示 + 预估时间 + 取消按钮
  "AI 正在生成解析，预计 30 秒..."
  ████████░░░░░░░░  50%

超长等待（> 60s）：
  Toast 提示 + 后台通知机制
  "解析正在后台生成，完成后通知你"
```

### 9.3 错误处理 UI

```
网络错误：
  Toast 提示（右上角，3秒消失）
  "网络请求失败，请检查网络连接"

表单验证错误：
  字段下方红色提示文字（inline）
  字段 border 变 danger 色

服务端错误（500）：
  页面级错误状态（大图标+说明）
  "服务暂时出了点问题，请稍后重试"
  提供"重试"按钮

Not Found（404）：
  友好的 404 页面
  提供导航回首页的按钮
```

### 9.4 确认对话框规则

```
需要确认的操作（例：重置对话、删除记录）：

┌─────────────────────────────┐
│  确认重置对话？              │ ← 简洁标题
│                             │
│  当前对话内容将被清空，      │ ← 简短说明（不超过2行）
│  无法恢复。                  │
│                             │
│  [取消]        [确认重置]    │ ← 危险操作用 danger 红色
└─────────────────────────────┘

规则：
  取消按钮在左，确认按钮在右
  危险操作确认按钮用 danger 色
  确认文字具体说明动作（"确认重置" 不是 "确认"）
```

## 十、无障碍规范

### 10.1 必须遵守的 a11y 规则

```
1. 颜色对比度：
   正文文字（小）vs 背景：≥ 4.5:1
   大文字/图标：≥ 3:1
   严禁以颜色作为唯一信息载体

2. 键盘可访问：
   所有交互元素可通过 Tab 键到达
   focus 状态必须可见（focus-visible:ring）
   操作可通过 Enter/Space/Escape 触发

3. 语义 HTML：
   使用 <button> 而非 <div onClick>
   使用 <nav>, <main>, <aside>, <section>
   图片必须有 alt 属性

4. ARIA：
   动态内容更新：aria-live
   对话框：role="dialog" + aria-modal
   展开/收起：aria-expanded
   加载状态：aria-busy

5. 动效：
   prefers-reduced-motion 必须处理（见第六章）
```

- [ ] 颜色使用符合语义色彩系统
- [ ] 字体层级正确（不过度使用 font-bold）
- [ ] 间距使用 Tailwind 默认单位，不随意 magic number
- [ ] 暗色模式 dark: 前缀已覆盖

**交互完整性**
- [ ] hover/focus/active/disabled 四态都处理
- [ ] 加载状态有骨架屏
- [ ] 空状态有设计
- [ ] 错误状态有 Toast/inline 提示

**响应式**
- [ ] 手机（375px）、平板（768px）、桌面（1280px）三个断点都验证过
- [ ] 文字在小屏不截断或遮挡
- [ ] 弹窗在小屏是底部 sheet 而非居中模态框

**无障碍**
- [ ] 键盘可以 Tab 到达所有交互元素
- [ ] focus ring 可见
- [ ] 图片有 alt

**性能**
- [ ] 没有不必要的 re-render（组件 memo 合理）
- [ ] 大图懒加载
- [ ] 动效有 prefers-reduced-motion 处理
