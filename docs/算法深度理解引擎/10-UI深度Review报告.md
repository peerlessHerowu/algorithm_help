# UI 深度 Review 报告

> 评审范围：`ui-preview/` 全部 6 个 HTML 文件 × 5 个 Spec 文档 × PRD
> 评审视角：产品体验 · 用户流程 · 逻辑自洽 · 设计一致性 · 扩展性 · 安全 · 可发现性
> 评审日期：2026-06-21

---

## 一、总览评价

### 1.1 整体印象

方案A（Geist 极简暗色）+ 补充模块是覆盖最全面的 UI 原型，涵盖了 12+11=23 个页面区域。
方案B/C/D 各自只覆盖了核心 4 个场景（首页、题目列表、题目详情、费曼模式），作为风格对比参考。

### 1.2 覆盖率评估

| 维度 | 现状 | 目标 |
|------|------|------|
| 页面覆盖 | 方案A 23个区域 | Spec 定义 25 个功能区域 |
| 交互状态 | 部分页面有加载/错误态 | 每个页面应覆盖正常/加载/空/错误 4 态 |
| 响应式 | 仅桌面端 | 需覆盖移动端关键页面 |
| 风格一致性 | 方案A内部一致 | B/C/D 仅作参考，最终选一个落地 |

## 二、逐页面深度 Review

### 2.1 首页（Hero + 特色功能 + 热门题目）

**覆盖情况**：✅ 方案A/B/C/D 均有实现

**正面评价**：
- 价值主张明确："五级深度 × AI 图解 × 模式提炼"一句话说清核心差异
- 数据指标（500+题/23模式/5层级）建立信任感
- 热门题目入口降低首次使用门槛

**问题与建议**：

| # | 问题 | 严重程度 | 建议 |
|---|------|----------|------|
| H1 | "500+题目解析"与实际 MVP 50题不符，上线时会造成期望落差 | 🟡中 | 改为动态数字或"50+精选深度解析"，后续按实际增长 |
| H2 | 无用户登录态感知——新用户 vs 回访用户看到一样的首页 | 🟡中 | 已登录用户首页改为"继续学习"Dashboard（今日复习/上次学到/推荐） |
| H3 | CTA "开始学习"跳转目标不明确 | 🟢低 | 匿名→题目列表，已登录→个性化推荐或上次学习位置 |
| H4 | 缺少社会证明（用户评价/学习数据/成功案例） | 🟢低 | V2 再加，MVP 先用数据指标支撑 |
| H5 | 方案B/C/D的首页功能卡片缺少"面试模拟""间隔复习"等后期功能 | 🟢低 | 统一对齐方案A的6个功能卡 |

## 三、跨页面用户流程 Review

### 3.1 新用户首次体验流程

```
首次访问 → 首页 → 点击"开始学习" → 题目列表 → 选题 → 详情页(L3) → 阅读 → ?
```

**问题**：阅读完一道题后，用户流程断裂。缺少"下一步"引导。

**建议流程**：
```
阅读完 → "这道题对你有帮助吗？"反馈 → "试试用费曼模式复述？"引导 → 
  或 "看看同模式的变体题？"推荐 → 形成持续学习循环
```

### 3.2 面试准备者流程

```
登录 → 选择目标公司(Google) → 按公司筛选题目 → 逐题学习(L3/L4) → 面试模拟 → 评分 → 薄弱点训练
```

**问题**：
- 按公司筛选功能 UI 缺失（L1问题）
- 从面试评分报告到"薄弱点训练"的跳转路径不存在
- 缺少"面试准备计划"功能（如"Google面试30天计划"）

### 3.3 日常复习流程

```
登录 → 首页看到"今日5道待复习" → 进入复习中心 → 翻卡片 → 自评 → 完成
```

**问题**：
- 首页缺少"今日复习"提示入口（对已登录用户）
- 复习完成后缺少正向激励（"太棒了！今日复习完成 🎉"）
- 复习中途退出后重新进入，是从头开始还是继续？需要明确


### 3.4 内容生成触发流程

```
用户进入某题详情 → 发现某级别未生成 → 点击"触发生成" → 等待 → 生成完成 → 自动展示
```

**问题**：
- "触发生成"按钮在 UI 中未展示（D1问题）
- 等待期间用户看什么？需要有生成进度的实时反馈
- 生成失败后的恢复路径：重试按钮 + 降级提示"查看已有级别内容"

### 3.5 错误恢复流程

**网络断开**：
- 当前：无任何提示
- 建议：顶部 Banner "网络断开" + 自动检测恢复后消失 + 费曼/面试页保存本地草稿

**AI 服务不可用**：
- 当前：无降级方案展示
- 建议："AI暂时繁忙"提示 + 引导浏览预生成内容 + 10秒后自动重试

**Token 过期**：
- 当前：仅认证页有示意
- 建议：全局拦截 401 → 静默刷新 token → 失败才弹出登录框
