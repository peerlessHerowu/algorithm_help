# 算法深度理解引擎 - 技术架构设计

> 文档版本：v1.0 | 更新时间：2026-06-21

## 一、总体架构

### 1.1 分层架构概览

```
┌─────────────────────────────────────────────────────────┐
│                     展示层 (Presentation)                 │
│   Web App (Next.js/Astro) | Chrome Extension | CLI      │
├─────────────────────────────────────────────────────────┤
│                     业务逻辑层 (Business)                 │
│   内容生成 | 图解引擎 | 模式识别 | 复习调度 | 面试模拟   │
├─────────────────────────────────────────────────────────┤
│                     AI 服务层 (AI Service)                │
│   AIProvider 统一接口                                    │
│   Kiro CLI | OpenAI | Anthropic | Ollama | DeepSeek     │
├─────────────────────────────────────────────────────────┤
│                     数据层 (Data)                         │
│   本地文件(MD/JSON) | SQLite | MySQL | Redis       │
├─────────────────────────────────────────────────────────┤
│                     数据源层 (Source)                     │
│   LeetCode | Codeforces | 牛客 | 洛谷 | AtCoder | URL  │
└─────────────────────────────────────────────────────────┘
```

### 1.2 核心设计原则

1. **接口抽象优先**：所有外部依赖通过接口隔离，更换实现不改业务代码
2. **静态内容为主**：70%+ 内容预生成，运行时零成本
3. **渐进式复杂度**：MVP 极简（文件系统），逐步引入数据库和服务
4. **离线优先**：核心功能不依赖网络，AI 交互为增强功能
5. **可插拔架构**：图解引擎、AI 提供者、数据源均可独立替换

## 二、AI 服务层设计（核心）

### 2.1 AIProvider 统一接口

```typescript
// 核心抽象接口 — 后续换 AI 只改实现，不改调用方
interface AIProvider {
  // 生成题目完整解析
  generateExplanation(problem: Problem, options: GenerateOptions): Promise<Explanation>
  
  // 用户思路转化为结构化答案
  transformUserInput(input: UserInput): Promise<StructuredAnswer>
  
  // 生成图解描述（Mermaid/SVG代码）
  generateDiagram(algorithm: Algorithm, type: DiagramType): Promise<DiagramCode>
  
  // 交互式追问/费曼模式
  interactiveChat(context: ChatContext, message: string): Promise<ChatResponse>
  
  // 错误检测
  detectErrors(content: string): Promise<ErrorReport>
  
  // 分级解释生成
  generateLeveledExplanation(topic: Topic, level: Level): Promise<LeveledContent>
}

// 生成选项
interface GenerateOptions {
  level: 1 | 2 | 3 | 4 | 5           // 解释级别
  languages: ProgrammingLanguage[]     // 目标语言
  includeSteps: boolean                // 是否包含逐步流程
  includeDiagrams: boolean             // 是否包含图解
  includeApplications: boolean         // 是否包含应用映射
}
```


### 2.3 智能路由层（成本控制核心）

```
┌─────────────────────────────────────────────────┐
│                  用户请求                         │
└────────────────────┬────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────┐
│      Layer 1: 静态内容层（零成本）                │
│  预生成的标准解析、Mermaid 图、模板代码           │
│  命中率目标：70%                                 │
└────────────────────┬────────────────────────────┘
                     ▼ 未命中
┌─────────────────────────────────────────────────┐
│      Layer 2: 本地模型层（零边际成本）            │
│  Ollama + 轻量模型                              │
│  处理：格式转换、简单问答、代码补全              │
└────────────────────┬────────────────────────────┘
                     ▼ 能力不足
┌─────────────────────────────────────────────────┐
│      Layer 3: Kiro/云端 AI（按需付费）           │
│  复杂推理、创意类比、深度分析、新题实时解析      │
└─────────────────────────────────────────────────┘
```

路由决策逻辑：
1. 先查静态缓存（已生成的内容）
2. 判断任务复杂度：简单→本地模型，复杂→云端
3. 用户可配置偏好（节省成本 vs 最佳质量）

## 三、数据模型设计

### 3.1 核心实体

```typescript
// 题目
interface Problem {
  id: string                    // 统一ID
  title: string
  difficulty: 'easy' | 'medium' | 'hard'
  tags: string[]                // 算法标签
  platforms: PlatformMapping[]  // 各平台映射
  description: string
  constraints: string[]
  examples: Example[]
}

// 平台映射
interface PlatformMapping {
  platform: 'leetcode' | 'codeforces' | 'nowcoder' | 'luogu' | 'atcoder'
  id: string                    // 平台上的ID
  url: string
  frequency: number             // 出现频率/热度
  companies: string[]           // 考过的公司
}

// 完整解析
interface Explanation {
  problemId: string
  level: 1 | 2 | 3 | 4 | 5
  sections: {
    intuition: string           // 直觉/类比
    approach: Approach[]        // 多种解法
    stepByStep: StepTrace[]     // 逐步流程
    diagrams: Diagram[]         // 图解
    complexity: ComplexityAnalysis
    patterns: PatternRef[]      // 关联模式
    applications: Application[] // 应用映射
    mathFoundation: MathRef[]   // 数学基础
    references: Reference[]     // 权威引用
    summary: string             // 总结
  }
}

// 解法
interface Approach {
  name: string                  // 解法名称
  idea: string                  // 核心思路
  code: CodeBlock[]             // 多语言代码
  timeComplexity: string
  spaceComplexity: string
  whyThisWorks: string          // 为什么正确
  whenToUse: string             // 什么时候用
  limitations: string[]         // 局限性
}
```

### 3.2 知识图谱数据结构

```typescript
// 算法模式
interface AlgorithmPattern {
  id: string
  name: string                  // 如"滑动窗口"
  category: string              // 所属大类
  template: CodeBlock[]         // 模板代码
  signals: string[]             // 使用信号（什么时候该想到这个模式）
  variants: PatternVariant[]    // 变体列表
  relatedProblems: string[]     // 关联题目ID
  prerequisites: string[]       // 前置知识
  nextSteps: string[]           // 进阶模式
}

// 题目关联关系
interface ProblemRelation {
  from: string                  // 题目ID
  to: string                    // 题目ID
  type: 'prerequisite' | 'variant' | 'similar_pattern' | 'follow_up' | 'harder_version'
  description: string           // 关系描述
}

// 学习路径
interface LearningPath {
  id: string
  name: string                  // 如"动态规划从入门到精通"
  description: string
  nodes: LearningNode[]
  estimatedHours: number
}

interface LearningNode {
  type: 'pattern' | 'problem' | 'math' | 'application' | 'paper'
  id: string
  order: number
  isOptional: boolean
  unlockCondition?: string      // 解锁条件
}
```

## 四、图解引擎设计

### 4.1 架构

```
用户请求图解
    ↓
图解类型决策器（根据算法类型自动选择）
    ↓
┌─────────────┬─────────────┬─────────────┐
│ Mermaid渲染 │ SVG生成器   │ Canvas动画  │
│ (流程/树/图)│ (静态图解) │ (交互动画) │
└─────────────┴─────────────┴─────────────┘
    ↓
前端渲染组件（统一渲染接口）
```

### 4.2 图解类型决策规则

```typescript
function chooseDiagramType(algorithm: Algorithm): DiagramConfig {
  const rules: Record<string, DiagramConfig> = {
    'array': { type: 'canvas', subtype: 'pointer-animation' },
    'linked-list': { type: 'svg', subtype: 'node-link' },
    'tree': { type: 'mermaid', subtype: 'tree-graph' },
    'graph': { type: 'mermaid', subtype: 'flowchart' },
    'dp': { type: 'canvas', subtype: 'table-fill' },
    'backtracking': { type: 'mermaid', subtype: 'decision-tree' },
    'sorting': { type: 'canvas', subtype: 'bar-animation' },
    'sliding-window': { type: 'canvas', subtype: 'window-slide' },
    'binary-search': { type: 'canvas', subtype: 'range-shrink' },
    'heap': { type: 'svg', subtype: 'tree-array-dual' },
    'union-find': { type: 'svg', subtype: 'forest' },
    'string': { type: 'svg', subtype: 'char-alignment' },
  }
  return rules[algorithm.category] || { type: 'mermaid', subtype: 'flowchart' }
}
```

## 五、内容生成流水线

### 5.1 批量预生成流程

```
1. 题目列表获取
   └→ 从各平台获取题目元信息
   
2. 优先级排序
   └→ 按热度、频率、经典程度排序
   
3. 题解聚合
   └→ 抓取各平台高赞题解（注意合规）
   
4. AI 精炼生成
   └→ 通过 Kiro CLI 批量生成：
      - L2/L3 级别解析（最常用）
      - 图解 Mermaid 代码
      - 多语言代码
      - 模式标签
   
5. 质量校验
   └→ AI 自审 + 规则校验（代码可编译、复杂度正确）
   
6. 存储入库
   └→ 按统一格式存储到 data/ 目录
```

### 5.2 实时生成流程

```
用户请求（如输入思路、自定义输入、交互追问）
    ↓
路由决策器
    ↓
┌─ 命中缓存 → 直接返回
├─ 简单任务 → 本地模型处理
└─ 复杂任务 → Kiro/云端AI处理
    ↓
结果缓存（下次同请求直接命中）
    ↓
返回用户
```

## 七、"不走AI"的降级方案

当 AI 不可用或需要节省成本时的 fallback 策略：

| 功能 | AI方案 | 非AI替代方案 |
|------|--------|-------------|
| 流程解析 | AI生成逐步说明 | 预写模板+变量替换 |
| 图解 | AI生成Mermaid代码 | 基于算法类型的图模板，数据填入 |
| 代码注释 | AI生成中文注释 | 静态的预生成注释 |
| 复杂度分析 | AI推理 | 基于规则自动推导（递归→主定理） |
| 模式匹配 | AI语义理解 | 基于标签的规则匹配 |
| 间隔重复 | AI生成变体题 | SM-2算法（纯数学，无需AI） |
| 类比生成 | AI创意生成 | 预置的类比库（人工精选） |
| 错误检测 | AI审校 | 静态分析（AST解析代码正确性） |

## 八、安全与合规

### 8.1 数据来源合规

- 遵守各平台 robots.txt 和 ToS
- 不直接复制原文，AI 重新组织表达
- 标注内容来源，尊重原作者
- 用户自行导入的内容由用户负责

### 8.2 API Key 安全

- 所有 Key 通过环境变量注入，不硬编码
- 前端不直接调用 AI API，通过后端代理
- 支持 Key 轮换和额度监控
