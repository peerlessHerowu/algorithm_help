# 算法深度理解引擎 - 分级解释系统设计

> 文档版本：v1.0 | 更新时间：2026-06-21

## 一、设计理念

### 1.1 为什么需要分级

传统算法教学的致命问题：**"一刀切"式解释**。

- 对新手：太抽象、跳步多、术语密集→放弃
- 对专家：太啰嗦、太基础、没深度→无价值

分级解释让同一知识适配不同认知层次，每个人都在自己的"最近发展区"内学习。

### 1.2 五级体系总览

| 级别 | 代号 | 核心风格 | 信息密度 | 代码占比 |
|------|------|----------|----------|----------|
| L1 | 直觉级 | 纯类比+故事，零术语 | 最低 | 0% |
| L2 | 入门级 | 具体例子+图+伪代码 | 低 | 30% |
| L3 | 进阶级 | 模式框架+代码+对比 | 中 | 50% |
| L4 | 熟练级 | 优化+证明+工程实践 | 高 | 40% |
| L5 | 专家级 | 论文+数学+前沿 | 最高 | 20% |

## 二、各级别详细规范

### 2.1 L1 直觉级

**目标受众**：零编程基础、跨行业人士、想建立算法直觉的人

**写作规则**：
- 绝不出现代码
- 每个概念配一个生活类比
- 用"你"的口吻对话
- 例子不超过5个元素
- 可以"不严谨但不错误"
- 结尾一句话总结核心直觉

**方法组合**：类比(★★★) + 动画(★★★) + 故事化(★★★) + 渐进提示(★★★) + 认知锚点(★★★)

**模板结构**：
```
1. 生活场景引入（一个你熟悉的场景）
2. 场景中的问题（自然引出算法要解决的问题）
3. 直觉解法（你第一反应会怎么做）
4. 类比总结（一句话记住核心）
5. [可选] 多类比接力（换一个角度再理解一次）
```

**示例（Dijkstra L1）**：

> 想象你在一个城市里要打车去机场，有很多条路可以走，每条路花的钱不同。
>
> 你的策略是：从当前位置看看附近所有路口，哪个"到目前为止总花费最少"，就先去那里。到了之后再看它附近的路口。不断重复直到到达机场。
>
> 这就像一滴水从你脚下开始慢慢扩散——先到近的地方，再到远的地方。
>
> 🎯 **一句话记住**：总是先去"当前最便宜能到"的下一站。

### 2.2 L2 入门级

**目标受众**：刚学编程1年内、能看懂基本语法

**写作规则**：
- 术语首次出现必须解释
- 每个步骤配图（至少状态变化图）
- 用最小的输入走完整流程（3-5个元素）
- 先伪代码，再正式代码
- 代码每行有注释
- 边界情况明确列出

**方法组合**：动画(★★★) + 代码追踪(★★★) + 渐进提示(★★★) + 对比图(★★★)

**模板结构**：
```
1. 题目理解（用自己的话重新描述题目）
2. 最小例子（3-5个元素）
3. 直觉思路（从暴力开始想）
4. 逐步图解（每一步的状态图）
5. 伪代码（中文描述逻辑）
6. 正式代码（逐行注释）
7. 执行追踪表（用例子走一遍每行代码）
8. 边界情况清单
9. 复杂度（直觉解释，不用公式）
```

**示例（两数之和 L2 片段）**：

> **题目理解**：给你一个数组和一个目标数，找出数组中哪两个数加起来等于目标数。
>
> **最小例子**：数组 [2, 7, 11, 15], 目标 = 9
>
> **逐步图解**：
> ```
> 步骤1: 看第一个数 2，需要找 9-2=7
>         哈希表: {} → {2: 0}
>         [2, 7, 11, 15]
>          ^
> 步骤2: 看第二个数 7，需要找 9-7=2
>         2 在哈希表里！位置是 0
>         找到答案: [0, 1]
> ```

### 2.3 L3 进阶级

**目标受众**：学算法1-3年、能套模板但不灵活

**写作规则**：
- 重点是"模式"和"框架"
- 必须有多解法对比
- 标注"什么信号下该用这个方法"
- 揭示底层共同思路
- 与类似题目建立联系
- 代码精简，不需逐行注释

**方法组合**：模式模板(★★★) + 苏格拉底追问(★★★) + 对比图(★★★) + 极端化思考(★★★)

**模板结构**：
```
1. 模式识别（这题属于什么模式？信号是什么？）
2. 多解法概览（暴力→优化→最优）
3. 核心解法详解（框架代码+关键点）
4. 解法对比矩阵
5. 底层共同框架提炼
6. 变体与迁移（改变什么条件会怎样）
7. 模板代码（通用、可复用）
8. 关联题目网络
```

**示例（滑动窗口 L3 片段）**：

> **模式识别信号**：当你看到"连续子数组/子串" + "满足某条件" + "最长/最短"，80%是滑动窗口。
>
> **通用框架**：
> ```python
> def sliding_window(s, condition):
>     left = 0
>     window = {}  # 窗口内状态
>     result = 0
>     
>     for right in range(len(s)):
>         # 1. 扩大窗口：右边界元素入窗
>         window[s[right]] = window.get(s[right], 0) + 1
>         
>         # 2. 收缩窗口：不满足条件时左边界右移
>         while not condition(window):
>             window[s[left]] -= 1
>             left += 1
>         
>         # 3. 更新答案
>         result = max(result, right - left + 1)
>     
>     return result
> ```
>
> **迁移**：这个框架直接套用于：
> - LC 3 (最长无重复子串) → condition = 无重复字符
> - LC 76 (最小覆盖子串) → condition = 包含所有目标字符
> - LC 209 (长度最小子数组) → condition = 和≥target

### 2.4 L4 熟练级

**目标受众**：3-5年经验、算法工程师、资深面试准备

**写作规则**：
- 边界条件完整分析
- 复杂度有推导过程（不只是结论）
- 工程实践注意点
- 面试追问应对
- 优化技巧和常数优化
- 可以使用数学符号

**方法组合**：变式练习(★★★) + 自我解释(★★★) + 反面教材(★★★) + 跨域迁移(★★★)

**模板结构**：
```
1. 完整复杂度推导
2. 边界条件完整列表+处理策略
3. 常见错误与陷阱
4. 优化技巧（常数优化、空间优化）
5. 面试追问 Q&A
6. 工业级实现注意点
7. 实际应用场景（具体案例）
8. 相关工程问题（如何scale到大规模）
```

**示例（Dijkstra L4 片段）**：

> **复杂度推导**：
> - 每个节点最多入队一次：V次 extract-min
> - 每条边最多松弛一次：E次 decrease-key
> - 二叉堆实现：extract-min O(logV)，decrease-key O(logV)
> - 总计：O((V+E)logV)
>
> **面试追问**：
> - Q: "如果有负权边？" → A: Dijkstra 失效，用 Bellman-Ford O(VE)
> - Q: "如果图特别稠密(E≈V²)？" → A: 用数组实现O(V²)更好
> - Q: "10亿节点怎么办？" → A: 分层图/Contraction Hierarchies

### 2.5 L5 专家级

**目标受众**：研究者、资深算法工程师、竞赛高手

**写作规则**：
- 引用原始论文
- 包含数学证明或证明思路
- 标注理论局限性
- 列出开放问题
- 讨论计算复杂性下界
- 与前沿研究建立联系

**方法组合**：论文引用(★★★) + 数学推导(★★★) + 前沿应用(★★★) + 跨域迁移(★★★)

**模板结构**：
```
1. 历史脉络（谁、何时、为什么提出）
2. 形式化定义与正确性证明
3. 最优性分析（下界论证）
4. 与其他算法的理论关系
5. 变体与泛化（学术研究方向）
6. 前沿应用（近5年论文）
7. 开放问题
8. 完整参考文献
```

**示例（Dijkstra L5 片段）**：

> **历史**：Dijkstra, E.W. (1959) "A note on two problems in connexion with graphs"，原文仅2页，在咖啡馆中约20分钟构思完成。
>
> **正确性证明(循环不变量)**：
> 设 S 为已确定最短距离的节点集合。
> 不变量：∀v∈S, d[v] = δ(s,v)（d[v]等于真实最短距离）
> 
> 归纳步骤：设 u 是下一个被选中的节点(d[u]最小)。
> 反证法：假设存在更短路径 s→...→x→...→u，其中 x∉S。
> 但 d[x] ≥ d[u]（因为u是最小的），且边权非负，
> 所以 δ(s,u) ≤ d[x] + w(x,...,u) ≤ d[u]。矛盾。∎
>
> **理论下界**：
> 在 comparison-based 模型下，单源最短路的下界是 Ω(E + V log V)?
> Thorup (1999) "Undirected SSSP with Positive Integer Weights in Linear Time" 
> 证明了无向图整数权可以 O(E + V) 线性时间。
>
> **前沿变体**：
> - D* Lite (Koenig & Likhachev, 2002): 动态环境增量更新
> - Quantum Dijkstra (Dürr et al., 2006): O(√V · polylog)
> - 在 RL 中的类比: Value Iteration 本质是 Bellman-Ford 的固定点迭代

## 三、级别切换与自适应

### 3.1 用户级别判定

**初始判定**（三选一）：
1. 用户自选
2. 入口测试（5道快速判断题）
3. 默认 L3（最通用）

**动态调整规则**：
| 用户行为 | 级别变化 |
|----------|----------|
| 连续跳过类比/基础解释 | 建议升级 |
| 在追踪练习中频繁出错 | 建议降级 |
| 主动点击"更深入" | 临时展示高一级 |
| 主动点击"更简单" | 临时展示低一级 |
| 模式识别quiz正确率>80% | 建议升级 |
| 模式识别quiz正确率<40% | 建议降级 |

### 3.2 级别间的平滑过渡

每个级别的解释都包含"向上/向下"的入口：

```
L2 解释底部:
  "想更深入？→ 看看 L3 的模式框架和变体分析"
  
L4 解释顶部:
  "需要回顾基础？→ L2 有逐步图解帮你温习"
```

### 3.3 混合级别模式

用户可以对不同模块选择不同级别：
- 思路分析：L3
- 代码实现：L4
- 数学基础：L2
- 应用映射：L5

这种"混搭"是真实学习的常态——你可能代码很强但数学基础薄弱。

## 四、同一知识完整五级示例（动态规划）

### L1: 直觉级

> 想象你在爬楼梯，每次可以爬1步或2步。你想知道到第10阶有多少种走法。
>
> 笨方法：把所有可能的走法都列出来数一遍——太累了！
>
> 聪明方法：到第10阶的走法 = 到第9阶的走法 + 到第8阶的走法。因为最后一步要么从第9阶跨1步上来，要么从第8阶跨2步上来。
>
> 这就像记菜谱——做过一次就记下来，下次直接用，不用重新想。
>
> 🎯 **一句话记住**：大问题拆成小问题，小问题的答案记下来不重复算。

### L2: 入门级

> **什么是动态规划？**
> 把一个大问题拆成更小的子问题，先算小的，用小的结果算大的。关键是：把算过的结果存起来，避免重复计算。
>
> **逐步走流程**（爬楼梯，n=5）：
> ```
> dp[1] = 1  （到第1阶只有1种走法）
> dp[2] = 2  （到第2阶有2种：1+1 或 2）
> dp[3] = dp[2] + dp[1] = 3
> dp[4] = dp[3] + dp[2] = 5
> dp[5] = dp[4] + dp[3] = 8
> ```
> [图：楼梯图，每个台阶标注dp值和来源箭头]

### L3: 进阶级

> **DP 四步框架**：
> 1. **定义状态**：dp[i] 代表什么？
> 2. **写出转移方程**：dp[i] 和之前的状态什么关系？
> 3. **确定初始条件**：最小的子问题答案是什么？
> 4. **确定计算顺序**：从小到大还是从大到小？
>
> **信号**：当你看到"最优"/"方案数"/"可达性" + "可以拆分为子问题" + "子问题有重叠"，想DP。
>
> **与贪心的区别**：贪心每步选局部最优；DP考虑所有子问题的组合找全局最优。

### L4: 熟练级

> **空间优化**：当转移只依赖前1-2个状态时，可以滚动数组O(1)空间。
>
> **常见陷阱**：
> - 状态定义不够：如背包问题必须包含"容量"维度
> - 计算顺序错误：0-1背包必须倒序遍历容量
> - 初始化遗漏：dp[0]的值直接影响全局正确性
>
> **复杂度推导**：状态数 × 每个状态的转移代价 = 总时间
> - 1维DP：O(n) × O(1) = O(n)
> - 2维DP：O(n×m) × O(1) = O(nm)
> - 区间DP：O(n²) × O(n) = O(n³)

### L5: 专家级

> **DP 的形式化基础**：Bellman (1957) "Dynamic Programming" 一书确立理论框架。最优子结构 + 重叠子问题是DP适用的充要条件。
>
> **与其他范式的关系**：
> - DP = 记忆化的穷举（本质是搜索+剪枝）
> - DP 与 贪心：贪心是DP的特例（当局部最优=全局最优时）
> - DP 与 分治：分治的子问题不重叠（merge sort），DP的子问题重叠
>
> **计算复杂性视角**：
> DP 在多项式时间解决的问题类 ⊂ P。但不是所有P问题都有自然的DP解。
> 某些问题（如TSP）用DP可以做到O(2^n × n)，这比暴力O(n!)好，但仍是指数级。
>
> **前沿**：
> - 在 RL 中：Bellman方程是强化学习的基础
> - 参考：Sutton & Barto "Reinforcement Learning" Ch.3-4

## 五、Prompt 工程指南

### 5.1 生成各级别的 Prompt 模板

```
你是一个算法教学专家。请为以下算法/题目生成 L{level} 级别的解释。

级别规范：
- L1: 纯生活类比，零代码，零术语，一句话核心直觉
- L2: 具体例子+逐步图解+伪代码+逐行注释代码
- L3: 模式框架+多解法对比+模板代码+迁移题目
- L4: 复杂度推导+边界分析+面试追问+工程实践
- L5: 论文引用+数学证明+前沿变体+开放问题

题目/算法：{topic}

要求：
1. 严格按照级别规范写
2. {level-specific requirements}
3. 图解用 Mermaid 格式
4. 权威引用精确到章节
```

生成后自动检查：

- [ ] L3是否提炼了模式？（必须有）
- [ ] L4是否有复杂度推导？（必须有）
- [ ] L5是否有论文引用？（必须有）
- [ ] 是否有跳步/逻辑断裂？
- [ ] 例子是否完整可验证？
