# 算法深度理解引擎 - AI 成本与降本策略

> 文档版本：v1.0 | 更新时间：2026-06-21

## 一、成本量级估算

### 1.1 单次调用成本

| 场景 | Token量(输入+输出) | 成本(Claude/GPT-4级) | 成本(DeepSeek) |
|------|-------------------|---------------------|----------------|
| 生成一题完整解析 | ~4000-6000 | $0.05-0.15 | $0.005-0.02 |
| 分级解释(单级) | ~2000-3000 | $0.03-0.08 | $0.003-0.01 |
| 图解生成(Mermaid) | ~500-1000 | $0.005-0.02 | $0.001-0.003 |
| 用户交互追问(单轮) | ~1000-2000 | $0.01-0.04 | $0.001-0.005 |
| 链接解析+精炼 | ~3000-5000 | $0.04-0.12 | $0.004-0.015 |
| 错误检测 | ~1500-2500 | $0.02-0.06 | $0.002-0.008 |

### 1.2 全量内容生成成本估算

| 内容规模 | 题目数 | 每题成本(含多级) | 总成本 |
|----------|--------|-----------------|--------|
| MVP(核心50题) | 50 | $0.30 | ~$15 |
| V1.0(经典200题) | 200 | $0.30 | ~$60 |
| V2.0(LeetCode TOP 500) | 500 | $0.30 | ~$150 |
| 全量(2000题) | 2000 | $0.30 | ~$600 |

**结论**：全量预生成是一次性投入，完全可接受。

## 二、六大降本策略

### 策略1: 预生成 + 静态缓存（节省 90%+）

**原理**：所有标准内容离线批量生成，存为静态文件，运行时零成本。

**实施**：
1. 用 Kiro CLI headless 模式批量生成
2. 结果存为 JSON/Markdown 文件
3. 前端直接读取静态文件
4. 仅当内容不存在时才实时调用 AI

**覆盖范围**：
- 所有预选题目的 L2/L3 标准解析
- 预生成的 Mermaid 图解代码
- 模式模板和关联关系
- 多语言代码版本
- 标准例子的逐步流程

**命中率目标**：70% 的用户请求直接命中缓存

### 策略2: Prompt 缓存（节省 40-90%）

**原理**：Anthropic/OpenAI 的 prefix caching 机制——重复的 system prompt 只计费一次。

**实施**：
- 设计稳定的长 system prompt（包含规则、格式要求、知识库）
- 每次请求的 system prompt 完全相同，只有 user message 变化
- Anthropic Claude 的 prompt caching 可节省 90% 的重复 token 费用

**适用场景**：实时交互（费曼模式、追问、错误检测）

### 策略3: 模型分层（节省 50-70%）

**原理**：简单任务用便宜模型，复杂任务用强模型。

| 任务类型 | 推荐模型 | 成本级别 |
|----------|----------|----------|
| 格式转换、代码翻译 | GPT-4o-mini / DeepSeek | 极低 |
| 简单问答、代码注释 | Qwen3-Coder (本地) | 免费 |
| 标准题解生成 | Claude Sonnet / GPT-4o | 中等 |
| 深度分析、创意类比 | Claude Opus / GPT-4 | 较高 |
| 论文解读、数学推导 | Claude Opus | 最高 |

**判断逻辑**：
```
if 任务 in [格式转换, 代码翻译, 语法检查]:
    use cheap_model
elif 任务 in [标准解析, 流程生成]:
    use medium_model  
elif 任务 in [创意类比, 深度分析, 论文解读]:
    use best_model
```

### 策略4: 本地模型（零边际成本）

**原理**：用 Ollama 运行本地模型，一次部署永久免费。

**推荐本地模型**：

| 模型 | 参数量 | VRAM需求 | 适用任务 |
|------|--------|----------|----------|
| Qwen3-Coder 3B | 3B | 4GB | 代码补全、格式转换 |
| Qwen3-Coder 7B | 7B | 8GB | 代码解释、简单问答 |
| Llama 3.3 8B | 8B | 8GB | 通用对话、文本生成 |
| DeepSeek-Coder-V2 16B | 16B | 16GB | 高质量代码分析 |

**部署方式**：
```bash
# 安装 Ollama
curl -fsSL https://ollama.com/install.sh | sh

# 拉取模型
ollama pull qwen3-coder:7b

# API 调用（兼容 OpenAI 格式）
curl http://localhost:11434/v1/chat/completions \
  -d '{"model": "qwen3-coder:7b", "messages": [...]}'
```

**适用场景**：
- 代码语言转换（Python → Java）
- 代码逐行注释生成
- 简单的格式化和结构化
- 基本的代码正确性检查

### 策略5: 模板化生成（节省 70-80%）

**原理**：用结构化模板 + 变量填充，减少 AI 参与比例。

**示例**：流程解析模板

```markdown
## {{algorithm_name}} 执行流程

### 输入
- 数组: {{input_array}}
- 目标: {{target}}

### 步骤 {{step_number}}
- 当前状态: {{state_description}}
- 操作: {{operation}}
- 结果: {{result}}
- 变量变化: {{variable_changes}}

### 复杂度
- 时间: {{time_complexity}} — 因为 {{time_reason}}
- 空间: {{space_complexity}} — 因为 {{space_reason}}
```

**AI 只需要填充变量值**，而非生成整个结构。

### 策略6: 增量生成（按需节省）

**原理**：不一次生成全部内容，用户需要什么才生成什么。

**实施**：
- 默认只加载 L2/L3 级别（最常用）
- 用户切换到 L1/L4/L5 时才触发生成
- "展开更多"按钮后面的内容按需加载
- 图解默认用简单版，点击"详细图解"才生成复杂版

## 三、前期自用的最佳方案

### 3.1 推荐方案：Kiro CLI + 静态生成

```
┌───────────────────────────────────────────┐
│         内容生成阶段（离线/批量）           │
│                                           │
│  Kiro CLI (headless) ──→ JSON/MD 文件     │
│  手动触发，按需批量生成                    │
└───────────────────┬───────────────────────┘
                    ▼
┌───────────────────────────────────────────┐
│         内容消费阶段（在线/实时）           │
│                                           │
│  静态网站 ←── 读取 JSON/MD 文件           │
│  交互功能 ←── Kiro IDE 内直接对话          │
└───────────────────────────────────────────┘
```

**优势**：
- 零运营成本（Kiro 已有）
- 生成质量高（Claude Opus 级别）
- 内容可版本控制（Git）
- 不依赖任何外部服务

**劣势**：
- 生成速度受限于 Kiro 并发
- 无法支持多用户实时交互
- 需要手动触发生成

### 3.2 Kiro CLI 使用方式

```bash
# 方式1: 通过 Kiro IDE 交互式生成
# 在 Kiro 中打开项目，发送 prompt 生成内容

# 方式2: Kiro CLI headless（如果支持）
export KIRO_API_KEY=your-key
kiro --no-interactive --prompt "为 LeetCode #1 两数之和生成 L3 级别完整解析..."

# 方式3: 脚本化批量生成
for problem_id in $(cat problem_list.txt); do
  kiro --no-interactive --prompt "$(cat prompts/generate_explanation.md) 题目: $problem_id"
  sleep 5  # 避免限流
done
```

## 四、"不走AI"的完整 Fallback 方案

当 AI 完全不可用时，系统仍能提供核心价值：

| 功能 | AI方案 | 非AI替代 | 质量损失 |
|------|--------|----------|----------|
| 流程解析 | AI生成 | 预写模板+变量替换(MadLibs式) | 中等 |
| 图解 | AI生成Mermaid | 按算法类型匹配图模板+数据填入 | 低 |
| 代码注释 | AI生成 | 预生成的静态注释 | 低 |
| 复杂度分析 | AI推理 | 规则引擎(递归→主定理自动推导) | 低 |
| 模式匹配 | AI语义理解 | 基于标签的规则匹配 | 中等 |
| 间隔重复 | AI生成变体 | SM-2算法(纯数学) | 无 |
| 类比生成 | AI创意 | 预置类比库(人工精选) | 高 |
| 错误检测 | AI审校 | AST静态分析+规则检查 | 中高 |
| 面试追问 | AI对话 | 预设追问题库 | 中等 |
| 费曼交互 | AI引导 | 预设引导问题模板 | 高 |

### 降级体验设计

```
正常模式（AI可用）：
  完整交互体验 → 实时生成 → 个性化解释

降级模式（无AI）：
  静态内容浏览 → 预生成解析 → 标准图解 → 规则化练习
  
  用户感知：
  - 仍有高质量内容（预生成的）
  - 缺少交互式追问和个性化
  - 没有实时的费曼模式
  - 用提示语告知："切换到AI模式获得更丰富体验"
```

## 五、成本监控与预警

### 5.1 监控指标

| 指标 | 阈值 | 动作 |
|------|------|------|
| 日均API费用 | > $5 | 邮件通知 |
| 单次请求Token | > 10000 | 截断并提示 |
| 缓存命中率 | < 60% | 分析热点，补充预生成 |
| 本地模型命中率 | < 30% | 检查路由逻辑 |
| 单用户日调用次数 | > 50 | 限流提示 |

### 5.2 成本优化闭环

```
监控 API 费用
    ↓
分析高成本请求类型
    ↓
判断：能否预生成？能否用本地模型？能否模板化？
    ↓
实施优化 → 验证效果 → 循环
```

## 六、未来成本趋势预判

| 时间 | 预期变化 | 应对策略 |
|------|----------|----------|
| 2026 H2 | GPT-5发布，4级模型降价 | 更多任务下放到便宜模型 |
