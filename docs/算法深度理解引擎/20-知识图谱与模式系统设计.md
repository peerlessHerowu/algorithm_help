## 一、产品定位

### 1.1 核心价值

单道题的学习是点状的，知识图谱让学习变成网状：

```
用户视角的价值：

做完"两数之和"之后…
  ├─ 「我应该做哪道题？」→ 推荐：三数之和 / 四数之和 / 和为 K 的子数组
  ├─ 「这题用了什么模式？」→ 哈希表查找 / 双指针
  ├─ 「这个模式在哪里还能用？」→ 字母异位词 / 无重复字符的最长子串
  └─ 「我的薄弱点在哪？」→ 双指针模式正确率只有 45%，需要加强
```

### 1.2 当前数据现状

| 表 | 条数 | 缺口 |
|----|------|------|
| graph_node | 50 | 目标 200+（模式节点 30 + 题目节点 170+） |
| graph_edge | 110 | 目标 500+（关联关系太少，图谱太稀疏） |
| algorithm_patterns | 20 | 目标 50+（核心模式全覆盖） |
| cross_domain_mapping | 10 | 目标 75+（15 个核心模式 × 5 维度） |

ALTER TABLE graph_node

## 六、推荐系统：「做完这题还应做」

### 6.1 推荐算法

```
推荐逻辑（按优先级）：

1. 同模式 + 更高难度（进阶推荐）
   权重 0.4 × 关联边权重 × (1 - 用户已完成率)

2. 同模式 + 相似难度（巩固推荐）
   权重 0.3 × 关联边权重 × (1 - 用户完成)

3. prerequisite 关系的下一步（路径推荐）
   权重 0.2 × 关联边权重

4. 用户薄弱模式的题目（针对性推荐）
   权重 0.1 × (1 - 薄弱模式正确率)

最终按综合分排序，取 Top 5
```

```java
@Service
public class PatternRecommendService {

    public List<RecommendedProblem> recommend(String problemId, String userId) {
        // 1. 获取该题所属模式
        List<String> patterns = graphNodeRepo.findPatternsByProblemId(problemId);

        // 2. 获取用户已完成题目（避免重复推荐）
        Set<String> completed = userProgressRepo.findCompletedProblems(userId);

        // 3. 获取用户薄弱模式
        Set<String> weakPatterns = trainingStatsRepo.findWeakPatterns(userId, 0.6f);

        // 4. 图遍历查找候选（1-2跳以内）
        List<GraphEdge> edges = graphEdgeRepo.findBySourceIds(
            graphNodeRepo.findNodeIdsByProblemId(problemId));

        // 5. 计算推荐分
        return edges.stream()
            .map(e -> {
                String targetProblemId = e.getTargetProblemId();
                if (completed.contains(targetProblemId)) return null;

                float score = computeRecommendScore(
                    e, patterns, weakPatterns, userId);
                return new RecommendedProblem(targetProblemId, score, e.getRelationType());
            })
            .filter(Objects::nonNull)
            .sorted(Comparator.comparingDouble(RecommendedProblem::getScore).reversed())
            .limit(5)
            .collect(Collectors.toList());
    }
}
```

## 九、性能设计

### 9.1 图谱数据加载优化

```
策略：分层加载 + 缓存

Layer 1：首屏只加载模式节点（30个）+ 高频题目（Top 100）
  → 数据量小（<5KB），秒级加载

Layer 2：用户展开某个模式时，懒加载该模式的题目节点
  → 按需请求 /api/v1/graph/subgraph?center={patternId}

Layer 3：完整图谱数据
  → 用户明确操作"显示全部"时加载
  → 后台预计算压缩后的 JSON（gzip < 100KB）
  → Redis 缓存 6 小时
```

### 9.2 推荐结果缓存

```java
// 每 6 小时预计算热门题目的推荐结果
@Scheduled(cron = "0 0 */6 * * *")
public void precomputeRecommendations() {
    // 取 Top 500 热门题目
    List<String> hotProblems = problemRepo.findTopByViewCount(500);

    for (String problemId : hotProblems) {
        List<RecommendedProblem> recs =
            recommendService.recommend(problemId, null); // null = 通用推荐
        String key = "recommend:problem:" + problemId;
        redisTemplate.opsForValue().set(key, toJson(recs), 6, TimeUnit.HOURS);
    }
}
```
